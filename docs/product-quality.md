# Agent Harbor 产品质量标准与当前差距

> 阅读范围：这是2026-10-30的阶段质量评审，正文的“当前差距”保留当时语境，不是当前版本的缺陷清单。现行功能见[产品文档](index.md)，具体实现限制须对照当前源码与目标环境验证。

核实日期：2026-10-30。面向付费用户的验收标准；不是已达到企业生产交付的声明。

## 用户应当获得的结果

用户交付需求后，应能知道任务是否被接收、当前处于哪个阶段、最近发生了什么、拿到哪一个可使用的版本，以及失败后怎样继续。执行结束不等于应用可用；模型估算费用不等于平台扣费；调用工具不等于工具完成。界面必须保留这些区别。

## 本轮已实现

| 问题 | 调整 | 验证方式 |
| --- | --- | --- |
| 多处操作失败只处理登录过期，其余错误被忽略 | 统一错误处理对非登录错误给出明确提示 | 异常处理代码核查及类型检查 |
| 失败后空白，只显示“已停止” | 每条失败/中断结果显示解释及继续入口；旧记录没有原因时明确原因未记录，不推断用户停止 | 历史消息实际页面、状态测试 |
| 系统超时被写成用户取消 | 保存停止原因，超时为失败并显示具体原因；应用操作也区分生成超时 | 执行生命周期及消息状态测试 |
| 工具已开始就显示完成 | 只展示“已调用”，不冒充成功回执 | 真实旧任务页面检查 |
| 应用里模型选择没有实际传到执行 | 网页请求、HTTP接收、应用操作及会话提交传递同一个模型；重试固定原模型和版本 | HTTP/数据库与客户端重试测试 |
| 刷新可能改变未确认请求的版本 | 用户/应用维度保存最近请求的原模型和原版本；本地保存失败时不发送请求 | 刷新恢复测试 |
| 生成、预览、发布混在一起 | 页面显示实际阶段、失败原因、继续修改/重试预览入口；标明初始模板 | 浏览器走查 |
| 未检查的版本也可直接发布 | 当前版本预览就绪后启用发布；生成/保存时不能发送冲突修改，但能写草稿和手动停止 | 页面及既有服务并发测试 |
| 初始模板缺少构建脚本，模型还要先修脚手架 | 模板直接提供 build/dev 脚本，减少无效工具调用 | 真实任务暴露问题后补修；生成应用同脚本构建通过 |
| 结束后的耗时仍继续走 | 开始/结束事件包含实际时间，网页据此固定耗时 | 事件还原测试 |
| SDK美元估算被误认为人民币账单 | 受管模型聊天不再展示SDK美元估算；人民币明细在账户页 | 页面及费用面板检查 |
| 全部余额预占被误认为余额耗尽 | 显示预占尚未扣费、真实余额及待核对说明，错误提供费用明细入口 | 费用面板与既有钱包测试 |

继续按钮只准备草稿，不自动发送，不覆盖已有草稿。重连不自动重放任务。正常查看页面不触发模型扣费。

## 尚未达到付费交付标准的部分

| 优先级 | 剩余问题 | 交付验收条件 |
| --- | --- | --- |
| P0 | 全余额预占仍可能因上游异常/进程崩溃保留为unknown；当前需管理员核对 | 覆盖取消、断流、服务崩溃、上游超时和重复结算的真实账务对账，异常有明确处理时限；不能靠无限等待 |
| P0 | 模型产出的应用是否满足需求，没有充分的真实任务验收 | 覆盖创建、续改、预览、发布、回滚，交付可操作应用与业务验收证据，而非仅模型返回成功 |
| P0 | 生产多租户隔离、授权与恢复没有完整验证 | 在目标部署环境完成租户越权、密钥泄漏、备份恢复和故障演练，明确恢复目标 |
| P1 | 工具缺少结构化完成/失败回执 | 端到端关联工具ID、开始/完成及可公开的结果；具备证据后再显示完成或失败 |
| P1 | 长时间没有输出时，不能区分模型思考、工具等待和上游卡住 | 有实际阶段事件和上游请求观测，显示可确认的等待来源；不使用假百分比 |
| P1 | 真实人民币费用尚未按单轮/应用完整汇总到编辑器 | 一轮包含多次模型调用，汇总实际扣费/未确认额，和账户账本一致 |
| P1 | 操作支持和异常处理主要依靠管理员手工核查 | 提供用户可用的支持渠道、参考编号和处理状态；管理员能定位对应证据 |
| P1 | 历史专家镜像行为不完全一致 | 明确兼容升级方案和用户可见版本；不能让旧会话悄悄套用不同策略 |

## 发布门槛

首轮改进可以用于本地复验，不能据此宣称完成千万级付费交付。每项正式上线能力需同时满足：真实业务结果可验、失败可恢复、费用可解释、权限可核实、运维有人负责。用户验收与真实供应商、生产环境验证单独记录。
