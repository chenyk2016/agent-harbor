> 阅读范围：本文件保留 V12 的交互改造记录、旧界面问题与当时验收，不作为当前全量功能清单。当前操作入口见[管理后台](../admin.md)。

## 一、原始要求

重新设计管理后台的页面结构与操作路径，让管理员能快速找到待处理事项、在上下文中完成用户/模型/扣费操作，而不是在长页面里寻找入口。

## 二、关联与隐含需求

| 用户表述 / 现状 | 隐含需求 | 本次处理 |

| 刷新后搜索、筛选、选中用户丢失 | 页面状态要可恢复、可分享 | 搜索、筛选、选中项、页码写入 URL |
| 管理后台和应用编辑页视觉语言不一致 | 沿用同一套 token、卡片、状态胶囊和空态 | 复用现有主题、`Pill`、`money`、卡片和列表规范 |

## 四、目标

1. **待办优先**：打开总览先看到需要处理的账号、模型和扣费，并能直接进入已筛选的页面。
2. **列表 + 详情**：用户和模型不再是一列长卡片，选中后在右侧完成操作。
3. **全局与个体分离**：赠送规则、全体赠送属于「计费设置」；单个用户的额度、Plus、流水属于用户详情。
4. **上下文化扣费核对**：在处理一笔扣费时看到用户、余额和预占，处理完保留页码。
5. **状态可恢复**：搜索、筛选、选中项和页码进入 URL。
6. **局部失败**：某个接口失败只影响对应区域，并给出重试。
7. **移动端可用**：列表与详情单页切换，详情可返回列表，表格横向滚动不撑破页面。

## 六、页面设计

### 6.1 外壳

- 侧栏 220px，白底，右边框；分组标题 10.5px，项目 36px，当前项 `brand.50` 底 + `brand.600` 字。
- 桌面不显示额外顶栏；每个页面使用现有 `PageHeader`，`showNavigation` 使用默认值，移动端菜单按钮直接打开侧栏抽屉。
- 侧栏底部显示当前管理员 ID 和「返回工作台」。
- 页面容器最大宽度 1280px；列表 + 详情页面使用满宽，不再限制 1120px。
- 所有页面共享：标题、说明、右侧主操作、最近读取时间、分区错误提示。

### 6.2 总览

```text
平台总览                                             [刷新]
先处理会阻塞用户的事项，再看配置。

需要处理
┌ 扣费待核对 3 ─────────┐ ┌ 未定价模型 2 ──────────┐ ┌ 同步待确认 1 ─────────┐
│ 最早 2 小时前 · reader │ │ 验收模型、…            │ │ 验收模型               │
│ [去核对]              │ │ [去定价]               │ │ [去核对]              │
└───────────────────────┘ └────────────────────────┘ └───────────────────────┘

平台概况
┌ 账号 12（正常 10 / 停用 2）┐ ┌ 模型 4（启用 3 / 未定价 2）┐ ┌ 钱包控制 已启用 ┐
└────────────────────────────┘ └─────────────────────────────┘ └─────────────────┘

运行边界（可折叠）
当前只展示数据库中的账号、配置和扣费状态；网关实时健康、延迟、供应商账单和资源监控尚未接入。
```

- 「需要处理」按风险排序：扣费待核对 → 未定价模型 → 同步待确认 → 已停用账号（有数据才显示）。
- 每张卡包含数量、对象摘要（最早请求/前 3 个模型名）和一个主操作。
- 链接带筛选参数：
  - `/admin/requests`
  - `/admin/models?filter=unpriced`
  - `/admin/models?filter=issue`
  - `/admin/users?status=disabled`
- 「平台概况」只展示能由现有接口得到的事实。
- 钱包未启用只出现一条警告，不与卡片重复。
- `Promise.allSettled` 分区加载；某个区块失败显示「读取失败 + 重试」，其他区块照常展示。
- 手动刷新；显示最近读取时间；不做后台轮询。

### 6.3 用户

```text
用户                                                 [刷新]
选中账号后在右侧处理额度、Plus 和停用。

┌ 用户列表 380px ────────────────┐ ┌ 用户详情 ────────────────────────────────┐
│ [搜索名称或 ID]  全部 正常 停用 │ │ reader  [正常] [Plus]        [赠送] [停用] │
│ 显示 3 / 共 3                   │ │ reader                    [编辑额度] [刷新] │
├─────────────────────────────────┤ ├───────────────────────────────────────────┤
│ reader        ¥10  预占 ¥0      │ │ 概览 | 额度与流水 | 资源额度               │
│ sample        ¥0                │ │                                           │
└─────────────────────────────────┘ │ 可用余额 / 预占 / 累计获得 / 累计消耗      │
                                    │ 最近流水 5 条                             │
                                    │ Plus 到期与设置                           │
                                    └───────────────────────────────────────────┘
```

- URL：`?user=ID&status=all|active|disabled&q=关键词`。
- 列表数据：`GET /admin/users` + `GET /admin/wallet` 并行加载；按用户 ID 合并余额、预占和 Plus。钱包未启用时隐藏余额列。
- 列表行：首字头像、名称、ID（mono）、状态胶囊、可用余额/预占、Plus 胶囊；点击整行选中。
- 默认排序：停用优先？不。按名称排序，搜索/筛选即时生效。
- 详情加载：`GET /admin/wallet/users/:id`；如果钱包未启用或读取失败，仍显示账号信息和资源额度。
- 详情头部动作：
  - 赠送：打开单用户赠送弹窗（金额、备注、预览、确认）。
  - 编辑额度：切到「资源额度」标签。
  - 停用/启用：保留现有确认弹窗和后果说明；不能停用自己。
- 标签：
  - **概览**：可用余额、预占、累计获得、累计消耗、本月消耗、Token 汇总；有待核对请求时显示一条警告；最近 5 条流水和最近 5 次模型请求，提供「查看全部」。
  - **额度与流水**：收支明细表（时间、说明、金额、余额），模型用量表（时间、模型、状态、扣费/预占、Token）；各显示最近 100 条，表内滚动。
  - **资源额度**：保存会话数、并行任务、保留环境、工作文件额度。文件额度用 MiB/GiB 输入并显示换算后的字节数；保存前显示将提交的值。
  - **Plus**（放在概览内的小卡）：当前到期时间、`datetime-local` 设置、取消 Plus（需确认）、说明「管理员开通，不涉及付款；每月最多发放一次」。
- 窄屏（<1180px）：列表占满；选中后进入详情单页，详情顶部显示「返回用户列表」。URL 仍保留 `user`。
- 空态：没有用户 / 没有匹配用户；选中用户不存在时显示说明和「返回列表」。
- 重新启用账号时保留现有说明：不恢复已撤销的密钥和登录。

### 6.4 模型与网关

```text
模型与网关                          [新增供应商] [新增模型] [刷新]
供应商与模型配置；密钥保存后不回显。

供应商
┌ 本地验收供应商 ────────────────┐ ┌ 其他供应商 ───────────────┐
│ anthropic_compatible · 1 个模型 │ │ …                          │
└─────────────────────────────────┘ └────────────────────────────┘

[搜索模型或上游标识]  全部 启用 停用 未定价 同步待确认

┌ 模型 ─────────┬ 供应商 ────┬ 上游 ────┬ 状态 ──┬ 价格（元/百万）┬ 使用范围 ┬ 启用 ┐
│ 验收模型       │ 本地验收    │ fixture  │ 已同步 │ ¥1 / ¥1        │ 全部用户  │ 是   │
└────────────────┴────────────┴──────────┴────────┴────────────────┴──────────┴──────┘
```

- URL：`?q=&filter=all|enabled|disabled|unpriced|issue&provider=ID&model=ID`。
- 供应商概览条：名称、协议、API 地址（截断）、模型数量；点击筛选该供应商。供应商只支持新增，不提供编辑/删除，因为后端没有对应接口。
- 模型表格列：名称、供应商、上游标识、同步状态、价格摘要（输入/输出）、使用范围（全部用户 / N 位）、启用状态。
- 筛选：
  - `unpriced`：`enabled && !price`。
  - `issue`：`state !== "ready"`。
  - 搜索匹配名称、上游标识、供应商名。
- 行点击打开右侧详情抽屉（桌面 520px，窄屏全屏）：
  - **基本信息**：名称、上游标识、供应商、说明、工具/流式能力、同步状态；启用开关。停用需要确认，说明会影响后续使用。
  - **价格**：输入、输出、缓存读取、缓存写入四个字段，单位「元/百万 Token」；显示当前值；保存价格。未配置价格时显示警告。
  - **使用范围**：当前允许用户以 chip 展示，可移除；添加用户使用可搜索的用户选择器（来自 `/admin/users`）；留空表示所有用户；保存使用范围。
- 「新增供应商」弹窗：名称、API 地址、上游协议、API Key；保存后清空密钥；说明保存后不回显。
- 「新增模型」弹窗：供应商、显示名称、上游模型标识、说明、工具/流式声明、允许用户；保存并同步。说明配置固定版本，更换上游请新增配置。
- 保持后端能力边界：不提供供应商编辑/删除、模型删除、密钥查看或真实健康检查。
- 空态：没有供应商时提示先新增供应商；没有模型时提示新增模型；筛选无结果时提示清除筛选。

### 6.5 扣费核对

```text
扣费核对                                             [刷新]
只处理用量未知的请求；确认依据后结算，已完成请求不会重复扣款。

共 3 笔 · 当前第 1 页 · 最早 2 小时前 · 读取于 17:04
[搜索当前页用户/模型/请求]  [全部] [超过24小时]

┌ 时间 ────────┬ 用户 ───┬ 模型 ────┬ 预占 ──┬ 备注 ────────┬ 操作 ┐
│ 10/30 17:04  │ reader  │ 验收模型 │ ¥10    │ 用量未确认   │ 核对 │
└──────────────┴─────────┴──────────┴────────┴──────────────┴──────┘

[上一页] [下一页]
```

- URL：`?offset=0&q=&age=all|24h`；`q` 和 `age` 只筛选当前页，界面必须写明「当前页筛选」。
- 表格行高 44px；时间列同时显示相对时长，超过 24 小时用 amber。
- 点击「核对」打开右侧抽屉：
  - 请求：模型、请求 ID（可复制）、备注、发生时间、预占上限。
  - 用户：名称、ID、可用余额、预占、Plus、停用状态；链接「打开用户详情」到 `/admin/users?user=ID`。
  - 表单：实际扣款（0 到预占上限，6 位小数）、核对依据与备注（必填，≤200 字）。
  - 错误只显示在抽屉内；提交成功后关闭抽屉并刷新当前页。
- 处理成功后保留 `offset`；如果当前页变空且 `offset > 0`，自动回到上一页。
- 「刷新」保留筛选和页码。
- 空态：「当前没有待核对请求」；读取失败显示重试。
- 说明保留：确认无消费填 0；重复提交相同金额和备注不重复扣款；列表变化后需刷新。

│ 每人金额 [ ]  备注 [ ]                                    │

- 赠送规则沿用 `PUT /admin/wallet/settings`。

- 预览必须展示人数、每人金额、合计和名单；确认按钮只在预览之后可用。
- 钱包未启用时显示一条警告，但规则仍可查看。

## 七、交互与状态规范

### 7.1 URL 状态

| 页面 | 参数 | 行为 |
| --- | --- | --- |
| 用户 | `user`, `status`, `q` | 选中用户、状态筛选、搜索词；用 `replace` 更新选择，刷新可恢复 |
| 模型 | `model`, `filter`, `provider`, `q` | 详情抽屉、筛选、供应商、搜索 |
| 扣费 | `offset`, `q`, `age` | 页码和当前页筛选 |
| 计费 | 无 | — |

### 7.2 加载、错误与空态

- 列表/表格加载显示骨架行或居中的 `Spinner`，不用纯文字「加载中…」。
- 每个数据源独立错误：总览按区块、用户列表/详情分开、模型列表/详情分开、扣费队列/用户摘要分开。
- 错误提示包含「重试」，不要清空已有数据。
- 空态区分：没有数据、没有匹配结果、未配置（如钱包未启用、没有供应商）、读取失败。

### 7.3 危险操作

- 停用/启用账号：保留现有确认弹窗和后果说明。
- 停用模型：新增确认，说明会影响后续请求；启用无需确认。
- 取消 Plus：新增确认。
- 下线/删除类能力后端没有，不新增。
- 赠送：保留预览 + 确认；批次号幂等。

### 7.4 视觉

- 沿用 `theme.ts` 和 `styles.css`：暖中性画布、白卡片、1px 边框、圆角 12px、Harbor 蓝主色。
- 表格、状态胶囊、空态复用应用编辑页的规范；状态不只靠颜色。
- 字号：正文 12.5–13px，表格 12px，元信息 11px，页面标题 22px。
- 金额统一用 `money()`；文件额度用 MiB/GiB，提交时换算字节。

### 7.5 无障碍

- 表格有表头；行点击用真实按钮或带 `tabIndex`/`role`，键盘可进入详情。
- 抽屉使用 Chakra `Drawer`，Esc 关闭，关闭后焦点回到触发按钮。
- 所有输入有 `aria-label`；必填和上限有可见说明。
- 状态胶囊带文字，不只颜色。

## 十、验收标准

### 功能

- 侧栏显示 5 个页面并分组；当前项高亮；移动端菜单可打开抽屉，页面标题旁有菜单按钮。
- 总览：待办卡显示数量与对象摘要，链接到已筛选页面；某个接口失败时其他区块仍显示并可重试。
- 用户：列表 + 详情；点击用户立即在右侧显示余额/Plus/额度；`?user=` 可刷新恢复；窄屏可返回列表。
- 用户详情：余额、预占、流水、模型用量、Plus 设置/取消、资源额度保存；文件额度按 MiB/GiB 输入并正确换算字节。
- 模型：供应商概览显示名称/协议/模型数；模型表格可按供应商、状态、未定价、同步问题筛选；搜索可用。
- 模型详情：价格摘要正确；四个价格字段保存后刷新；允许用户 chip 可增删，空表示所有用户；停用需确认。
- 新增供应商/新增模型在弹窗中完成；保存后列表刷新；密钥不回显。
- 扣费：表格显示用户、模型、预占、备注、相对时长；详情抽屉显示用户余额摘要；提交后保留页码，空页回退上一页。
- 计费设置：规则保存；指定用户/全体赠送预览人数、合计和名单；确认后刷新；批次号幂等说明保留。
- 所有页面在 1440 / 1024 / 390 宽度下无横向溢出；移动端抽屉和详情可操作。

### 质量

- `npm run check`、`npm run build:web` 通过。
- 使用 `tests/admin-verification.mjs` 的隔离夹具（或等价 mock）完成浏览器验收，覆盖加载、空态、错误、钱包未启用、未定价模型、待核对请求和窄屏。
- `npm test` 在配置 `AH_TEST_DATABASE_URL` 的环境通过；`npm run audit:public` 不新增 finding。
- 不发起真实供应商、模型或 Docker 应用调用。

## 十一、风险与取舍

| 风险 / 取舍 | 说明 | 缓解 |
| --- | --- | --- |
| 新增「计费设置」页 | 侧栏从 4 项变 5 项，管理员需要重新熟悉 | 分组标题明确「账号 / 平台」；总览待办卡直接链接 |
| 列表 + 详情 | 桌面需要更宽容器；窄屏多一次点击 | 用户/模型页使用满宽；`?user=`/`?model=` 可恢复；窄屏返回按钮 |
| 扣费筛选只作用于当前页 | 后端没有筛选参数 | 明确写「当前页筛选」，不误导为全局搜索 |
| 模型页信息量增加 | 表格列多，窄屏拥挤 | 窄屏横向滚动；详情抽屉承载编辑；价格/范围用摘要 |
| 拆分 WalletAdmin | 改动面较大，可能影响用户端钱包 | 只拆分展示组件，不改请求、金额和账本语义；逐项对照验收 |
| 总览分区加载 | 多个请求独立失败 | `Promise.allSettled` + 每卡重试；显示读取时间 |
| URL 状态 | 切换筛选会产生历史记录 | 选中项用 `replace`，分页用 `push` |
