# Agent Harbor 应用访客 Better Auth 改造规格

2026-11-06 · 技术方向已确认，待实施

新应用的访客认证目标采用 Harbor 托管的 Better Auth + PostgreSQL。账号仍按应用、预览或正式环境、登录方式隔离。Better Auth 负责验证邮箱密码或 Google 身份，Harbor 继续管理应用访客 ID、权限、停用和应用会话。既有 PocketBase 应用保持原认证后端。既有应用在新测试应用通过真实 Google、浏览器回跳与停用验收后逐个迁移。

## 1. 功能和边界

| 规格 | 预期行为 |
| --- | --- |
| VA-01 登录策略 | 沿用 `harbor-app.json` 中的 `public`、`required` 和登录方式声明。应用作者选择邮箱密码、Google 或两者。认证后端由 Harbor 的实例配置及环境记录确定。 |
| VA-02 邮箱密码 | 注册仍填写邮箱和密码，成功后直接进入当前应用，无验证码或发信依赖。账号唯一范围是应用、环境与登录方式。同一邮箱可在多个范围使用不同密码。 |
| VA-03 Google | 同一 Google 用户可分别进入不同应用及环境。用 Google 稳定用户标识匹配账号。Google 与邮箱密码独立，邮箱相同也不会合并。启用 Google 前用专用测试客户端和真实账号完成验收。 |
| VA-04 会话 | 每个应用主机签发自己的 Harbor 访客 Cookie。退出仅撤销当前应用会话。预览、正式、其他应用和工作台各自校验自己的凭据。 |
| VA-05 管理 | 应用所有者仍按应用及环境查看、停用和恢复访客。停用立即拒绝新会话并撤销当前范围的旧会话。恢复允许重新登录，旧会话保持失效。 |
| VA-06 兼容 | 保留现有登录页、应用端 `/__harbor/auth/*`、生成应用运行时及受保护预览流程。新版本发布和镜像回滚沿用该应用环境的认证后端和用户 ID。 |

首版范围是应用访客。工作台注册、钱包和管理员体系继续按工作台规格运行。邮箱找回、跨应用单点登录、账号合并、既有 PocketBase 数据迁移分别留待后续决策。

## 2. 数据与认证架构

- **由 Harbor 决定账号范围。** 用已部署的应用和环境记录定位范围，再校验本次方式是否启用。浏览器表单、生成代码和 OAuth 回调参数不能指定任意应用或数据库 schema。
- **复用已通过探针的隔离模型。** 每个已启用的「应用 × 环境 × 登录方式」对应独立 PostgreSQL schema，包含 Better Auth 所需表。由受控迁移模板创建，名称由服务端稳定 ID 生成。密码和 Google 都有独立命名与密钥。删除或重建部署时也使用原范围记录核对归属。
- **正式环境用有界连接池。** 优先验证 Better Auth PostgreSQL 适配器通过固定 `schemaName` 限定表名，同一认证服务共用有界连接池。避免为每个应用常驻一套连接池，也避免用请求参数切换共享连接的 `search_path`。探针验证了独立 schema，正式共享池方案仍须用交错并发请求验证。
- **数据库访问分权。** 运行角色只访问授权的访客认证表，初始化与清理使用单独权限。生成的应用容器仅访问自己的业务数据库和 Harbor 已校验的访客身份。正式与预览 Google 客户端配置分别管理。
- **保留 Harbor 访客 ID。** 扩展现有范围及账号映射，记录认证后端、登录方式、稳定的认证范围 ID 和外部用户 ID。应用看到的仍是 Harbor 访客 ID。账号映射唯一约束包含范围及来源。PocketBase 的集合和记录映射继续用于旧应用。
- **开通与清理可重试。** 初始化同一范围只建立一套凭据表。创建完成并校验归属后才发布认证入口。删除沿用应用删除的资源清理检查点，只清理经记录核对属于该应用的凭据表。恢复演练须同时核对认证表、Harbor 账号映射和应用业务数据。

## 3. 登录时序

1. **应用发起。** 应用运行时访问原有登录入口。Harbor 依据可信的部署记录校验应用来源、环境和返回路径，创建绑定当前浏览器的短期流程。
2. **邮箱密码。** Harbor 托管页按该流程选择密码范围，使用 Better Auth 服务端接口创建或验证凭据。密码交给 Better Auth 散列。Harbor 以验证后的用户 ID 查找或建立访客映射。
3. **Google。** Harbor 在固定认证域发起 OAuth。按部署环境配置固定回调，服务端持久化一次性 `state → 流程及账号范围`，并绑定浏览器、固定回调地址及有效期。回调先用记录路由到正确的 Better Auth 范围，再由 Better Auth 校验状态并换码。PocketBase 保留原回调路径，新后端使用独立回调路径。真实 Google 登录和 Chrome 回跳列为发布门槛。
4. **交接到应用。** 认证成功后，Harbor 复用现有一次性交接码回到应用域。原应用域在同一浏览器内兑换，签发应用自己的 Cookie。Better Auth 用于验证身份的临时会话不发给应用，回调完成后撤销或按短期生命周期回收。访客业务请求只使用 Harbor 应用会话。
5. **停用。** 管理操作仍由 Harbor 校验应用所有权。在同一业务事务内写停用标记并撤销已有应用会话。签发交接及兑换时重新核对停用，避免 OAuth 回调和停用并发时重新获得会话。账号恢复后需要新的登录流程。

## 4. 改动点

| 位置 | 实施内容 |
| --- | --- |
| `src/service/applications/visitor-auth/service.ts` | 把直接依赖 PocketBase 的账户操作收敛为后端接口，覆盖初始化、注册、密码验证、Google 发起和回调、账号查询和清理。按持久化的认证后端选择实现。复用现有访客映射、交接、会话与停用逻辑。 |
| `src/service/applications/visitor-auth/pocketbase.ts` 与新增 Better Auth 实现 | PocketBase 适配器继续服务已有范围。Better Auth 实现提供服务端凭据验证、范围初始化和固定 Google 回调的内部调用，收敛对应用侧可见的错误。 |
| `src/service/applications/visitor-auth/http.ts`、`config.ts` | 复用登录页、表单和来源限制，加入 Better Auth 固定 Google 回调和服务端范围分流。增加新范围默认后端及访客专用配置。 |
| `migrations/` 和应用部署记录 | 扩展范围、凭据映射和回调路由信息，兼容已有 PocketBase 数据。把选定后端持久化到范围，部署只引用该范围。新建、重试、重启和版本回滚均不会重选后端。 |
| `src/service/applications/service.ts` 与资源清理 | 在首次启用访客认证时初始化范围，成功后才发布路由。管理端按范围查询用户，删除应用按资源归属和原检查点完成清理。 |
| 部署、诊断和测试 | 核对数据库权限、回调、私有密钥、备份恢复和日志。增加双后端兼容、隔离、回调攻击与并发停用测试。业务应用模板优先沿用现有接口契约。 |

## 5. 实施与验收顺序

| 阶段 | 交付与通过条件 |
| --- | --- |
| 1. 隔离接入 | 在目标支持的 PostgreSQL 版本跑两个新应用、各自预览和正式。四个范围同邮箱不同密码；同一 Google 标识在四个范围各有独立用户；跨范围密码、Cookie、状态和回调被拒绝。并发连接下无串 schema，初始化可重试。 |
| 2. 真实浏览器与 Google | 只在全新测试应用上用真实 HTTPS 和专用测试账号，从页面完成 Google 授权、固定回调、应用域交接和工作台内预览。验证取消、重复回调、错误来源、退出及密码和 Google 账号独立。 |
| 3. 管理与恢复 | 验证应用所有者只能管理自己的访客，停用与正在回调的登录并发时不会产生有效会话。实测发布、回滚、重启和空环境恢复后访客 ID 与业务数据一致。回归旧 PocketBase 应用的注册、登录、停用和预览。 |
| 4. 新应用启用 | 验收后将 Better Auth 设为新建认证范围的默认值。发现故障时可关闭新范围开通或恢复新建默认值，已创建的范围仍按原后端和映射恢复。既有应用按下节的逐应用迁移门槛推进。 |

## 6. 既有 PocketBase 迁移门槛

先用新测试应用完成真实 Google 和浏览器验收。迁移前按应用及环境清点实际使用的密码集合、Google 集合、历史别名、停用账号和 Harbor 访客 ID。在可恢复备份上演练，预览先行，再处理该应用的正式环境。

密码需要保留原账号归属。若旧密码散列经独立验证可由目标版本安全承接，使用受控导入；否则设计旧凭据校验后写入新凭据的过渡期。Google 按供应商稳定用户标识与原记录核对。两种方式都以已有 Harbor 访客 ID 为业务归属，遇到重名、缺失映射或重复标识时停在原范围排查。

一次切换只处理一个应用环境。先核对旧会话、停用状态、业务数据和映射，保留可回退配置与旧凭据数据，再按新旧入口分别实测。完成备份恢复和授权数据核对后才结束该应用迁移。

已验证 Better Auth 1.7.18 的隔离原型，包括两个应用、四个环境范围、密码、会话、停用和 Google 替身回调。正式实现、真实 Google 授权、Harbor 端到端回跳及旧应用兼容仍待验收。 [隔离报告](../../var/evidence/visitor-better-auth/2026-11-06/REPORT.md)
