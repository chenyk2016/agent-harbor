# V11 统一对话入口与对话 / 应用分流

- 日期：2026-10-30
- 状态：待确认
- 依据：用户 2026-10-30 口述与参考截图（MOMA 首页：大输入区 +「任务助手 / 应用构建」切换）
- 影响范围：仅 `apps/web/src/**`，不改执行引擎、SDK、数据库和接口契约

## 一、原始要求

1. 需要有一个总的对话入口。入口可以选择对话和应用。
2. 对话列表也要通过图标区分。
3. 点击应用的对话，应该展示创建应用的那个编辑页面。
4. 对话和应用创建，不要二次弹窗，感觉多余。

## 二、关联与隐含需求

| 用户要求 | 隐含需求 | 本次处理 |
| --- | --- | --- |
| 总入口可选择对话 / 应用 | 入口必须是稳定可达的首页，而不是“有上次会话就自动跳走”；两种模式要有视觉区分；切换模式不丢已输入内容；应用模式受创建权限约束 | `/` 改为常驻入口；顶部分段切换「对话 / 应用」；切换时保留文本 |
| 总入口 | 提交后必须落到正确目的地：普通对话进会话页，应用进应用编辑页；失败不能丢文本 | 对话模式「发送即创建会话并发出第一条消息」；应用模式「发送即创建应用并打开编辑页」 |
| 总入口 | 入口要保留现有创建能力：选模型、技能版本快照、幂等请求编号、创建中防重复 | 复用 `ModelPicker`、`api.create`（含技能快照）、`clientRequestId` |
| 对话列表图标区分 | 不能只靠颜色区分；要有可读标签；普通会话与应用会话的点击行为不同 | 列表行首改为类型图标：普通对话 `MessageSquare`，应用会话 `LayoutGrid`，并带 `aria-label` / Tooltip |
| 点击应用会话展示编辑页 | 需要知道会话属于哪个应用；旧链接 `/sessions/:appSessionId` 也要落到编辑页；命令面板“最近会话”同样分流 | 通过已有 `GET /applications` 建立 `sessionId → appId` 映射；列表与命令面板直接链到 `/applications/:appId`；会话页发现是应用会话时 `replace` 重定向 |
| 创建不要二次弹窗 | 删除「新建会话」弹窗及其状态；`+`、⌘N、命令面板「新建会话」统一进入总入口；创建动作一次完成 | 删除弹窗；`+` / ⌘N / 命令面板都跳到 `/` 并聚焦输入区 |
| 创建不要二次弹窗 | 应用画廊已有独立的内联创建区，会与总入口形成第二套创建流程 | 移除画廊内联创建区，「新建应用」按钮跳到 `/?mode=app`（见待确认项 3） |
| 避免副作用 | 首页不再自动续接上次会话；原弹窗里的「初始内容 / 内置示例」选项会消失 | 会话列表仍在左侧，一键可回到任意会话；新会话默认空白，示例模板不再作为创建选项 |
| 避免副作用 | 应用名称原由创建表单单独填写 | 从需求首行派生名称（上限 40 字），创建后可在应用「设置」里改名 |
| 避免副作用 | 会话列表需要应用映射，但应用服务可能未开启 | `GET /applications` 失败（404/403）时静默视为“无应用会话”，不影响普通会话 |
| 避免副作用 | 新建会话时固定的模型与技能版本快照语义不能变 | 对话仍走 `api.create`，技能选择与模型快照保持原逻辑 |

## 三、交互设计

### 1. 首页总入口（`/`）

```text
┌ 会话列（现有） ┬────────────────────────────────────────┐
│ 搜索 / 列表    │        今天想推进什么？               │
│                │  ┌──────────┬──────────┐              │
│                │  │ 对话     │ 应用     │  ← 分段切换  │
│                │  └──────────┴──────────┘              │
│                │  ┌──────────────────────────────────┐ │
│                │  │ 描述一个目标，我来拆解并推进…    │ │
│                │  │                                  │ │
│                │  │ [模型 ▾]                    [↑] │ │
│                │  └──────────────────────────────────┘ │
│                │  辅助说明 / 错误提示                   │
└────────────────┴────────────────────────────────────────┘
```

- 顶部标题：「把目标交给 Agent」；副标题随模式变化。
- 模式切换：「对话」（`MessageSquare`）/「应用」（`LayoutGrid`），`role="tablist"`，当前项 `aria-selected`。
- 输入框：自适应高度（46–196px），Enter 发送，Shift + Enter 换行，输入法组合中不发送。
- 输入区底栏：`ModelPicker`（默认“使用默认模型”）+ 发送按钮。
  - 对话模式按钮文案 / `aria-label`：「开始对话」。
  - 应用模式：「创建应用」。
- 模式切换保留已输入文本；切换模式时清空错误提示。
- 应用模式可用性：
  - `GET /applications/config` 返回 `canCreate=true` → 可选。
  - `canCreate=false` → 标签禁用，提示「当前账号没有创建应用的权限」。
  - 接口 404（应用服务未开启）→ 标签禁用，提示「应用创建尚未开启」。
- 提交中：发送按钮 loading，整个输入区禁止重复提交。
- 失败：输入文本不清空，在输入区下方显示错误；401 / 账号停用仍交由现有 `problem()` 处理。

### 2. 对话模式：发送即创建

1. 由首条消息派生标题：取第一个非空行，压缩空白，最多 40 字；为空则「新的会话」。
2. 调 `api.create(title, "empty", undefined, modelId)`——保留技能版本快照和模型选择语义。
3. 创建成功后立刻用新的 `clientMessageId` 调 `POST /sessions/:id/messages` 发出首条消息。
4. 无论首条消息是否成功，都进入 `/sessions/:id`：
   - 发送成功：正常显示执行过程。
   - 发送失败（4xx / 网络）：把原文写回该会话草稿，进入会话页后可直接重试；不重复创建会话。
5. 创建本身失败：停留在入口，文本保留，显示错误。

### 3. 应用模式：发送即创建并打开编辑页

1. 由需求首行派生应用名称（最多 40 字；为空则「我的应用」）。
2. 调 `POST /applications`，携带 `title / prompt / modelId / clientRequestId`。
3. `clientRequestId` 在文本或模型变化时重新生成；同一文本重试复用原编号，避免重复创建。
4. 成功后把 `appId ↔ developmentSessionId` 记入本地映射，并跳转 `/applications/:appId`——即现有的应用编辑页（左对话、右预览 / 版本 / 发布）。
5. 失败（无权限、余额、服务未开启等）停留在入口，文本保留，显示 `explain(error)` 文案。
6. 不新增第二道确认、弹窗或表单页。

### 4. 会话列表分流

- 行首图标：
  - 普通会话：`MessageSquare`，中性色。
  - 应用会话：`LayoutGrid`，品牌色；Tooltip / `aria-label` 为「应用会话」。
- 状态（正在执行 / 已完成 / 失败 / 结果待确认）仍保留文字与颜色，不因图标调整而丢失。
- 普通会话点击 → `/sessions/:id`。
- 应用会话点击 → `/applications/:appId`。
- 应用编辑页中，该会话行保持选中态（按当前 `appId` 比对）。
- 列表头 `+`：跳到 `/` 并聚焦总入口输入区，不再创建空会话、不再弹窗。
- 空列表文案下方增加「开始新对话」按钮，进入总入口。

### 5. 深链与会话页兜底

- `/sessions/:appSessionId`（历史书签、旧链接）在确认映射后 `replace` 到 `/applications/:appId`。
- 应用映射加载完成前，会话页显示加载态，避免先闪出普通对话再跳走。
- 映射接口失败时按“无应用会话”处理，普通会话不受影响。

### 6. 应用编辑页布局

- `/applications/:id`（应用编辑页）维持 V10 规则：不显示左侧会话列，编辑区更宽。
- 编辑页左上角保留「返回应用列表」；从会话列表点入后，可用浏览器返回或该按钮回到应用列表。
- 应用画廊 `/applications` 同样不显示会话列。

### 7. 命令面板与快捷键

- `⌘/Ctrl + N`：跳到 `/` 总入口（默认对话模式），不再打开弹窗。
- 命令面板「新建」动作：名称改为「新建对话或应用」，跳到 `/`。
- 命令面板「最近会话」：应用会话显示 `LayoutGrid`，并直接打开应用编辑页。

## 五、接口与数据

不新增后端接口，复用现有：

| 接口 | 用途 |
| --- | --- |
| `GET /applications/config` | 入口判断应用创建是否可用、当前账号是否有权限 |
| `GET /applications` | 建立 `developmentSessionId → appId` 映射，供列表图标、点击分流、深链重定向 |
| `POST /applications` | 应用模式创建 |
| `POST /sessions` | 对话模式创建（含技能快照） |
| `POST /sessions/:id/messages` | 对话模式发送首条消息 |

`Workspace` 新增状态：

- `applications: Map<sessionId, { id, title, status }>`
- `appsLoaded: boolean`
- `applicationFor(sessionId): AppLink | undefined`
- `rememberApplication(app)` / `rememberApplications(list)`
- `startConversation(text, modelId): Promise<sessionId>`

映射刷新策略：工作台启动时加载；每 60 秒随会话列表轮询顺带刷新一次；本地创建应用、打开应用画廊 / 编辑页时立即回填。`GET /applications` 返回 404 / 403 时静默忽略。

## 六、不做什么

- 不改 `src/**` 的执行、会话、应用、钱包、数据库 schema 与 HTTP 契约。
- 不新增依赖、不引入状态库、不做前端全局 store。
- 不做会话重命名 / 删除 / 归档（后端没有对应能力）。
- 不把应用会话拆成独立的“应用对话”数据表。
- 不保留旧「新建会话」弹窗、模板选择器和首页自动跳转。
- 不在创建后自动发送、发布、改设置或触发其他后台动作。
- 不保证应用会话在其他标签页创建后 10 秒内出图标（最迟 60 秒轮询可见）。

## 七、验收标准

### 功能

- `/` 始终展示总入口，不再自动跳到上次会话；左侧会话列可见。
- 「对话」模式输入目标并发送：只创建一个会话、只发一条消息，落到 `/sessions/:id`。
- 「应用」模式输入需求并发送：只创建一个应用，落到 `/applications/:appId`，编辑页立即显示生成过程。
- 无应用创建权限 / 应用服务未开启：应用标签禁用并有明确提示，不发起请求。
- 发送失败：入口文本保留；对话首条消息失败时进入会话页且草稿为原文，可重试。
- 会话列表：普通会话显示对话图标，应用会话显示应用图标；点击应用会话进入编辑页。
- `/sessions/:appSessionId` 深链自动 `replace` 到 `/applications/:appId`。
- `+`、⌘N、命令面板新建均进入总入口，不出现任何创建弹窗。
- 应用编辑页与画廊均不显示左侧会话列，编辑页保留返回应用列表。

### 质量

- `npm run check` 通过。
- `npm test` 通过。
- `npm run audit:public` 通过。
- 1440 / 1180 / 900 / 375 宽度下入口与列表无横向溢出；键盘可完成模式切换、输入和发送。
- 浏览器实测（本地 fixture 或真实服务）：两种创建路径、失败路径、列表分流、深链重定向、命令面板与窄屏抽屉。
- 若本机 Docker / 服务不可用，明确标注“未做浏览器实测”，不以类型检查代替。

## 八、风险与取舍

| 风险 / 取舍 | 说明 | 缓解 |
| --- | --- | --- |
| 首页不再续接上次会话 | 老用户习惯“打开即回到上次工作” | 左侧会话列表保留，首项一键可达 |
| 不再能创建空会话 | 原弹窗可以先建会话再想内容 | 入口为“目标优先”；确有需要可在会话中清空后发送 |
| 丢失 `fix-project` 示例模板入口 | 原弹窗的“内置示例”选项被移除 | 本次接受；如需要，后续在入口加“示例”菜单 |
| 应用名称自动派生 | 首行可能不是理想名称 | 编辑页「设置」可直接改名，名称不影响发布地址 |
| 应用映射依赖 `/applications` | 应用服务关闭时接口 404 | 静默降级为普通会话，不影响使用 |

## 九、已确认决策

1. **首页形态**：`/` 直接作为总入口，不再自动续接上次会话。
2. **应用编辑页会话列**：维持 V10，应用编辑页不显示会话列。
3. **应用画廊内联创建区**：移除，统一从总入口创建应用。
