# Agent Harbor 工作台登录开发规格

> 阅读范围：本文件保留工作台认证的开发规格，不作为当前全部账号服务配置的说明。工作台邮箱认证使用 Better Auth；应用访客可选择 PocketBase 或 Better Auth，分别见[账号与登录](../identity.md)和[应用功能配置](../application-configuration.md)。

2026-11-06 · 认证方式、自助注册、10 元赠额及原管理员绑定已确认

> 当前部署与注册启用条件见[管理员与工作台登录](../identity.md)。

工作台使用 Better Auth 和现有 PostgreSQL。用户自行填写邮箱和密码，注册成功直接登录。注册免邀请码、验证码和邮件验证链接。页面沿用应用访客登录的卡片和表单样式。应用访客继续使用现有 PocketBase 账号和会话。

## 1. 用户可见行为

- **WB-01 注册。** 登录页可切换至「创建账号」。表单只有邮箱和密码。服务端去掉邮箱首尾空白、统一大小写，不折叠加号地址或点号。密码按原样传递，首版建议长度 12–128 字符。初始显示名由服务端生成。有效账号注册后直接打开工作台。重复提交、重复邮箱和失败重试均不能创建第二个账号或第二份资产记录。
- **WB-02 登录与退出。** 用户用邮箱和密码登录。错误邮箱和错误密码显示相同的提示。沿用工作台 8 小时会话期限，刷新页面或重启服务后，尚未到期的会话可继续使用。退出当前浏览器后，其他浏览器的有效会话可继续使用。退出不取消已运行的任务。
- **WB-03 普通用户权限。** 自助注册获得普通用户身份，仅能访问自己拥有的资源。原管理员账号、同邮箱的应用访客和其他 Harbor 用户各自保持独立。停用立即阻止后续鉴权，撤销该用户工作台会话和个人访问密钥，恢复后需重新登录。
- **WB-04 公开注册额度。** 公开自助注册的新用户一次性获得 10 元模型额度。开通前须确认使用受钱包约束的模型网关。测试需验证赠额恰好到账一次，余额耗尽后模型请求在供应商调用前被拒绝。若现有配置存在绕开钱包的模型路径，公开注册开放前须关闭该路径或补上同等的准入检查。其他开户方式沿用现有赠额策略。
- **WB-05 注册开关。** 工作台认证与公开注册分别控制。认证关闭时保持部署现有登录方式。认证开启但公开注册关闭时，已注册用户可继续登录。升级和恢复后按实例配置决定是否开放注册。

## 2. 改造清单与接口约定

| 改造位置 | 具体责任 |
| --- | --- |
| `apps/web/src/features/Login.tsx`、`app/App.tsx`、`state/api.ts` | 增加注册和邮箱登录表单、提交中及重试提示。注册或登录后通过 `/api/auth/me` 取得 Harbor 用户 ID，复用切换账号时清理旧数据的逻辑。旧标签页继续校验用户是否已变化。 |
| `src/service/identity/http.ts`、`src/service/http-api.ts` | 增加下表的两个同源入口，沿用 Harbor 的请求校验和错误格式。Better Auth 在服务端作为认证库调用，浏览器只访问列出的 Harbor 接口。注册由服务端补齐显示名。认证相关响应禁止缓存。 |
| `src/service/identity/store.ts`、`src/service/db/schema/identity.ts`、`migrations/` | 在现有 PostgreSQL 的实例 schema 中使用独立前缀的认证表，由项目迁移流程应用。用固定认证来源和 Better Auth 用户 ID 复用 `external_identities` 的唯一映射。认证成功后首次访问受保护接口时，原子创建 Harbor 用户、映射和钱包。失败回滚该事务，下一次访问可重试。 |
| `src/service/identity/http.ts`、`src/service/browser-sessions.ts` | Better Auth 会话只负责新浏览器登录。Harbor 继续检查停用、管理员和资源归属。新入口只签发 Better Auth 会话。迁移期间旧密钥入口按配置单独可用，带无效新会话的请求不得降级成旧浏览器身份。沿用会话撤销和连接中断机制，覆盖 Better Auth 会话 ID。 |
| `src/service/wallet/service.ts`、`src/service/identity/store.ts` | 为公开注册使用单独的初始化策略。沿用现有钱包账本和扣费逻辑，其他开户和赠额的行为保留。 |
| `src/service/config.ts`、`server.ts`、`.env.example`、`src/clients/ops/` | 配置工作台认证、注册开关、固定 HTTPS 来源和私有认证密钥。更新启动校验，使认证启用时可在无旧开发密钥文件的环境启动。诊断检查认证表和关键配置。备份与恢复检查认证表、Harbor 控制数据和必要私有配置。 |

| 接口 | 行为 |
| --- | --- |
| `GET /api/auth/config` | 保留现有字段，增加工作台邮箱登录和自助注册是否开放的标志。 |
| `POST /api/auth/register` | 仅在自助注册开放时接受 `email` 和 `password`。成功设置 Better Auth 会话 Cookie。校验失败或账号冲突返回可理解的错误，达到限流阈值返回 429。 |
| `POST /api/auth/password` | 接受 `email` 和 `password`。认证成功设置会话 Cookie。密码错误、账号不存在和账号不可用对外使用统一提示。 |
| `GET /api/auth/me` | 返回 Harbor 用户 ID 和已有权限字段。首次访问时补齐内部身份与账户。未认证或停用时拒绝业务访问，内部初始化失败返回可重试错误。 |
| `POST /api/auth/logout` | 撤销当前会话，清理 Cookie 并断开关联事件连接。迁移期间按当前会话类型退出。 |

## 3. 安全、兼容和迁移边界

- **可信边界。** 固定工作台公开来源。写请求必须通过同源检查，正式 Cookie 使用 HTTPS、HttpOnly 和仅当前主机可用的范围。限制请求体大小，按来源和账号对注册及登录限流。代理转发的客户端地址只信任已知代理。密码、会话凭据和认证密钥不进日志、前端持久存储或仓库。注册即登录时，重复邮箱响应可能被用来判断账号是否存在，限流须覆盖此路径。
- **邮箱边界。** 邮箱只是登录名。任何管理员授权、账号合并或资产迁移都不能凭用户填写的邮箱完成。首版范围是邮箱密码，Google、邮件找回、邮箱换绑和访客账号合并留给后续规格。没有可靠身份证据时，管理员不能仅凭邮箱重置账号或转移资产。
- **会话边界。** 退出只撤销当前会话。管理员停用覆盖该账号的所有浏览器会话、CLI 密钥和活动连接。停用与恢复并发时应保持安全，撤销未完成前账号保持不可用。认证源或会话库不可用时受保护请求应失败并可诊断。
- **原账号。** 正式切换前确认是否承接 `developer`。如需承接，操作者必须证明旧管理员身份和新登录身份，按内部 ID 建立绑定。新身份已绑定其他用户或已有新资产时拒绝自动合并。实现须提供在新身份首次进入前绑定的受控流程，避免先创建普通用户再迁移资产。
- **应用访客。** 应用访客的 PocketBase 集合、Cookie、路由、注册、预览与发布行为保持原契约。工作台启停无需启用应用访客认证。
- **发布范围。** 开发与隔离验收完成后，才进入目标环境启用和旧入口切换。回退优先关闭新入口、恢复既有受控入口，并保留新增数据及映射。旧入口无法覆盖新用户登录，因此回退预案须说明新用户的恢复路径。

## 4. 验收矩阵

| 编号 | 验收动作 | 通过条件 |
| --- | --- | --- |
| T01 对应 WB-01 | 在浏览器从零注册、退出后再用该邮箱登录。关闭所有邮件能力后重复。 | 无需验证码或邮件。注册后直接进入。重复邮箱、大小写变体及并发首次访问只对应一个 Better Auth 身份、一个 Harbor 用户和一个钱包。 |
| T02 对应 WB-02 | 测错误密码、未知邮箱、浏览器刷新、服务重启、会话到期和两个浏览器退出。 | 错误不泄露登录细节。有效会话可继续，过期会话被拒绝。退出只影响当前会话及其连接。 |
| T03 对应 WB-03 | 两个账号分别创建对话或应用，相互尝试读取、写入和打开管理接口。停用后再恢复其中一个。 | 资源和权限按内部 ID 隔离。停用撤销网页会话、CLI 密钥并断开活动连接。恢复后旧凭据不能重新使用。 |
| T04 对应 WB-04 | 公开注册、重复初始化、模拟耗尽新用户的模型额度，再尝试执行付费模型请求。 | 起始可消费额度为 10 元且只到账一次；未授权的模型请求在调用供应商前被挡住。既有赠额和管理员发放路径回归通过。用测试模型或记录网关是否收到请求验证。 |
| T05 对应 WB-05 | 分别关闭自助注册、关闭新认证、启用新认证并禁用旧网页密钥。 | 停止注册后现有用户可登录。关闭新认证后既有部署可按原配置运行。新认证独立启动和 CLI 鉴权通过。 |
| T06 攻击与异常 | 伪造来源、超量注册及登录、模拟初始化事务失败、提交失效会话并携带旧浏览器 Cookie。 | 写请求被拒绝或限流。故障重试可恢复且无半初始化账户。失效会话不会退回旧身份。 |
| T07 兼容和旧资产 | 回归活动报名访客登录及预览。用隔离副本演练原管理员绑定及冲突。 | 访客流程可用。绑定后内部 ID、原对话、文件、应用、余额和管理员权限相符。未授权绑定和冲突均被拒绝。 |
| T08 目标部署与恢复 | 用目标 HTTPS 地址跑 T01–T03 的主流程，检查 Cookie；备份后在空环境恢复，再演练关闭新入口。 | 真实账号、恢复后的数据归属、运维诊断和管理员恢复路径均可复验。目标环境验收记录单列。 |

开发验收要求运行类型检查、完整回归和公开审计，并保留专项结果。工程通过、目标环境上线和用户验收分别记录。

## 5. 实施顺序与需确认项

1. **认证与映射。** 先在隔离环境接库和迁移，走通注册、登录和已有权限。
2. **公开注册约束。** 实现限流、关闭注册开关、10 元一次性赠额及故障恢复，覆盖旧登录和访客回归。
3. **上线演练。** 核对正式 HTTPS、目标计费模式、旧管理员绑定和备份恢复，再切换入口。

已确认 Better Auth、邮箱密码自助注册和免验证，公开注册每个新账号一次性赠送 10 元。原 `developer` 通过受控操作显式绑定，正式绑定需要实际部署配置和用户选定的新邮箱及密码。
