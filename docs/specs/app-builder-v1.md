# 应用创建第一版：功能范围建议

日期：2026-10-26。状态：功能梳理稿，未实现、未部署。已按用户反馈收敛为公开预览、单固定域名和路径区分应用；具体部署方案仍为建议。

> 文档性质：2026-10-26 的范围建议快照，正文保留当时提出的目标与边界。2026-11-09 源码复核：创建、预览、发布、版本管理与永久删除已有实现；默认先归档、完整业务数据编辑、自定义域名等仍不是当前产品能力。访客登录及观测已有独立实现，不能再按本稿“账号体系后置”的早期范围判断。当前行为见[产品指南](../applications.md)。

## 目标与依据

用户输入一句需求，生成可运行的简单业务应用；通过持续对话修改，在右侧预览，再发布为有固定域名的应用，并能管理版本和业务数据。

已确认：第一版覆盖页面、表单、数据存储和基础接口。 发布路线由用户最终确定为“固定版本源码 → 构建产物 → 打包应用镜像 → 启动容器 → 网关转发”，每个已上线应用保持独立运行实例；源码、数据和历史产物独立持久保存。用户提供的两张截图分别作为「对话 + 预览」和「对话 + 应用管理」的信息布局参考，不代表要求复制其中全部功能。

用户本轮明确：无需私有预览，只有一个固定域名，希望通过地址后缀区分应用并简化部署。本稿将后缀解释为路径，例如`/apps/<appId>/`；这是设计假设，未读取实际域名。其余范围为建议，不是用户已确认的技术选型或实现承诺。属于 Agent Harbor 的新增能力，不合并或自动推进独立 app-builder-platform 项目。

## 第一版适用范围

- 支持展示页、简历、计算器、活动报名、反馈收集、简单清单和记录管理。
- 页面可以多页，支持路由、表单、基础数据增删改查和适配手机的布局。
- 应用在统一支持的运行模板内生成；技术栈、托管方式和容量在后续技术方案确定。
- 面向创作者开发和发布、访客使用、创作者管理数据三类操作。
- 复杂支付、多人协作、完整终端用户账号体系、多角色业务权限和长时间后台任务后置。

完整路径：我的应用 → 一句话创建 → 生成并验证 → 预览 → 对话修改 → 版本记录 → 发布 → 固定网址访问 → 工作台管理 → 修改后再次发布。

## 页面与布局

### 我的应用

- 应用卡片/列表：名称、缩略图、最近修改、开发状态、线上状态、当前线上版本和公开地址。
- 新建、搜索、重命名、进入编辑、打开线上地址、归档和删除。
- 删除已发布应用前明确下线与数据处理后果；默认先归档保留数据，永久删除另行确认。

### 应用编辑器

- 顶栏：返回应用列表、名称、当前版本、线上版本、「预览 / 工作台」切换、发布。
- 左侧常驻：对话、生成进度、版本成果卡片、输入框和附件入口。
- 右侧预览：路径、刷新、桌面/手机视口、独立窗口、加载/失败/休眠提示。
- 右侧工作台：应用概览、版本、发布与域名、数据、日志和设置。
- 切换右侧内容不停止生成；返回应用列表或关页也不取消已经接受的任务。
- 窄屏采用对话与预览切换；桌面可调整左右宽度。

## 创建与生成的行为

1. 用户说「做一个活动报名应用，有活动说明、报名表和名单管理」。
2. 系统立即创建应用记录并给出简短理解摘要。非关键选择使用合理默认；涉及支付、公开个人数据等关键不确定点再询问。
3. 显示「生成中 → 检查中 → 启动预览 → 可预览」。失败阶段显示原因与继续修复入口，保留需求和文件。
4. 成功后给出变更摘要、当前版本、预览入口。发现超出支持范围的需求明确说明，不用模拟按钮冒充真实服务。
5. 用户继续说「增加联系电话，并把页面改成暖色」，在同一应用工作草稿继续修改。

生成停止可能留下未完成修改；保留上一个可预览版本，并允许检查当前草稿、继续修复或从旧版本恢复。停止不等于自动撤销文件或数据变化。

## 持续预览

- 首次出现可运行页面后自动展示；在可运行检查点更新，不以每个文件写入事件强制刷新。
- 新草稿构建失败时继续显示最近成功预览，显式标注对应版本和最新错误，避免显示旧页面却标为新版本。
- 前端错误和预览服务错误可以由用户带入下一条修复消息；不承诺无限自动修复或无限模型消耗。
- 首版预览公开可访问，使用测试数据；可新窗口打开，不开发专门的预览登录、邀请或权限体系。公开范围包括预览内容，因此只使用示例数据，不放真实私密资料；业务管理接口继续鉴权。
- 路径区分应用不构成浏览器来源隔离；同域方案先按受信应用试用设计，不据此宣称可隔离任意用户代码。若控制台与应用共用来源，需单独评审管理身份暴露边界。
- 开发环境休眠后可恢复预览，并说明恢复中；与线上应用可用性分开。

## 版本的含义

- 工作草稿：AI当前编辑的文件，可能未完成或无法运行。
- 应用版本：不可变的源文件、锁定依赖、变更摘要、来源消息和检查结果；一次有效变更完成后编号，不为每个文件写入编号。
- 构建结果：某个版本生成的固定可部署产物，记录成功/失败和必要配置版本；密钥值不进入源码版本。
- 发布记录：哪个版本/产物在何时发布到哪个地址，记录结果；历史版本不必全部发布。
- 当前开发版本、正在预览版本和当前线上版本分别显示。
- 历史预览只读，恢复旧版本生成新的开发版本，并保留后续历史和全部对话；不删除历史消息假装回到过去。
- 第一版提供版本时间线、文字摘要和变更文件列表；分支、合并、多用户实时编辑和完整代码diff编辑器后置。

## 发布与域名

- 第一次发布分配固定域名下的路径，例如`https://<既有域名>/apps/<appId>/`，复用该域名HTTPS；发布确认展示目标版本、地址和数据变更提示。预览使用`/preview/<appId>/`。
- 复用用户已有固定域名的DNS与HTTPS入口，不新增通配子域名、逐应用证书或DNS API接入。实际域名和服务器尚未核实。
- 版本固定后再构建，完成启动及基础可达性检查后切换线上入口。失败保留原线上版本。
- 发布由用户触发；继续对话修改不自动改线上内容。刷新页面可以回查发布任务，不重复发起未知结果的发布。
- 后续更新保留同一公开地址；支持查看发布记录、下线、重新上线和兼容的线上代码版本回退。
- 发布后的应用有独立运行生命周期，退出编辑器、Agent环境休眠/回收不使其停止服务。
- 第一版不做域名绑定中心；应用管理展示固定域名加应用路径的完整网址，自定义域名后置。

## 数据与访问权限

- 各应用数据独立，平台管理数据与生成应用业务数据分开；应用访客不能读取 Harbor 控制面数据。
- 开发/预览使用测试数据，发布使用正式数据；不自动把示例报名或测试账号复制到线上。
- 第一版提供数据表/字段查看、记录列表、基本筛选、单条修改/删除和CSV导出；不做SQL控制台、可视化建模器或通用数据库平台。
- 每个接口明确公开/需创作者身份。报名示例可公开提交表单，名单查询、导出和修改仅创作者可用。
- 平台创作者身份与生成应用的访客身份分开；完整终端用户注册登录/组织/多角色后置，受限业务管理接口仍由服务端鉴权。
- 公共表单提供输入校验、基本频率/体积限制和安全错误提示。
- 生产数据结构默认只做兼容性扩展；删表、删字段、重置数据等破坏性变更首版拒绝自动执行。
- 代码版本恢复/回退不回滚业务数据；数据结构不兼容时阻止自动回退并说明原因。
- 上线前具有正式数据备份和人工恢复路径。完整数据库时间点回滚、任意数据迁移编排后置。

## 管理工作台范围

应用创作者工作台首版包含：

- 概览：名称、最近修改、当前预览/线上版本、公开地址、发布状态。
- 版本：历史版本、摘要、预览、恢复。
- 发布与域名：应用路径地址、发布记录、更新、回退、下线。
- 数据：业务记录查看、基本管理和导出。
- 日志：生成、构建、应用运行错误，按任务/版本查找，敏感字段脱敏。
- 设置：应用基本资料、标题/描述/图标、运行配置、代码导出、归档/删除。

平台运营侧保留最小应用台账、所有者、资源容量/发布占用和紧急下线能力，不与创作者工作台混用。

截图功能取舍：

| 截图入口 | 第一版建议 |
| --- | --- |
| 数据库 | 保留业务数据管理；不做数据库全功能控制台 |
| 域名管理、下载代码 | 保留固定域名下的路径地址与源码导出；自有域名后置 |
| SEO | 设置中保留页面标题、描述和图标；SEO评分/建议后置 |
| 数据分析 | 流量统计后置，首版先展示发布状态和运行错误，不展示伪造的PV/UV |
| 对话权限 | 创作对话仅所有者；不在首版扩展协作权限矩阵 |
| 接口文档/压测/限流 | 基础接口和必要保护由平台提供；文档门户、压测控制台、自定义限流面板后置 |
| 应用知识 | 先使用已有附件/Skill能力，不增加专属知识库系统 |
| 重置工作区 | 提供版本恢复；不提供一键清空正式数据库 |
| 分支、收藏、专家组与可视化选区编辑 | 不影响主流程，后置 |

## 与 Agent Harbor 当前能力的衔接

源码/文档静态核对：已有会话持有、持续输入、SSE、消息去重、中断/关闭、工作区文件、身份归属、Skill/专家、MCP及依赖环境，可作为生成执行基础。

待新增：App实体与应用工作区归属、开发会话绑定、可运行预览、应用版本、构建产物、发布任务、域名路由、应用长期运行、业务数据及相应管理界面。现有文件「预览」只显示文本，不等于应用交互预览。

第一版一个应用对应一个可写工作草稿和持续开发主对话，沿用单写入者约束；应用、对话、源码版本和线上部署分别保存，不将一个会话直接当作一个线上应用。

简化部署建议：同一服务器、统一入口、独立应用容器和共享数据库服务。控制面、Agent开发环境、构建发布、线上应用运行职责分开。线上应用不持有Agent模型凭据、MCP上游凭据、Harbor管理身份或Docker管理权限。复用既有SDK循环，不新增模型调度框架。

## 第一版验收样例

以「活动报名应用」贯穿验收：

1. 一句话创建，展示活动说明、报名表和适配手机的页面。
2. 预览可以完成真实测试报名，记录可在工作台查看；匿名访客不能读名单或修改数据。
3. 继续对话增加字段、修改样式，产生新版本，最近成功版本仍可查看。
4. 查看旧版本并恢复为新的开发版本，保留完整历史和对话。
5. 发布到既有域名下的HTTPS路径，独立浏览器可访问，正式数据库没有测试报名。
6. 继续修改不会改变已发布页面；再次发布在同一地址更新。
7. 新构建失败仍保留旧线上版本，发布响应丢失后可回查结果。
8. 编辑页关闭、开发容器回收后，线上应用仍可用。
9. 在数据结构兼容时回退线上代码，正式报名记录不丢失；不兼容时阻止自动回退。
10. 匿名访客可访问公开预览；其他创作者不能访问本应用的源码、日志、版本或管理数据。同域生成页面的浏览器身份风险另行验证。
