# 会话、任务与工作环境

## 三种不同操作

| 操作 | 行为 |
| --- | --- |
| 客户端断开 | 服务继续执行和保存事件；重连按游标补看 |
| 停止当前任务 | 原生interrupt，等待本轮结束，正常时保留环境 |
| 关闭工作环境 | 确认整个容器停止并删除，保留工作文件和原生对话 |

原生中断不撤销已修改文件或外部副作用，也不保证停止独立后台进程。收到中断回执不能立即提交下一轮，必须等本轮result和宿主收尾；5秒未结束则升级为整容器清理。任务总超时继续走强制清理。

Runner尚未把输入交给SDK时，中断直接移除待交付输入；原生回执仍显示待执行输入时按异常关闭。中断控制请求结束前不向宿主宣布本轮result，避免迟到中断影响下一轮。

## 正常连续对话

服务第一次执行时取得会话锁，先确认旧环境停止，再建立独立租约。首条消息创建Keeper和常驻Runner；同一条docker exec -i管道承载后续JSON消息。SDK query使用持续输入源，result只结束本轮。

正常成功或原生中断完成可以是`stopped=false + environment=ready`；中断结果为cancelled。`stopped=true`仅表示整个容器停止，不表示本轮是否已返回。状态未知为reconciling，禁止新的执行。

服务保存全部会话事件。后台任务按创建轮次归属；来源不明时messageId为空，不挂到新的前台消息。

## 空闲与退出

默认本轮结束后15分钟回收环境。正在执行时不计空闲，查看结果和后台日志不延长时限。到期停止全部容器进程，文件与对话保留；下一条新消息重新创建环境并resume，不恢复进程内存、端口或/tmp。

服务CLI的/exit、EOF、SIGHUP和SIGTERM只断开观看。执行中Ctrl+C明确停止本客户端提交的当前消息；关闭环境使用/close或close。旧cli:local调试入口仍随CLI退出关闭环境，必须使用独立数据根。

## 服务崩溃与重启

宿主每5秒更新独立租约；Keeper每5秒检查一次，心跳过期30秒后退出容器。这是兜底，不是精确回收时刻，也不能代替Engine状态检查。

重启时服务取得数据根锁，检查数据库版本，汇总数据库、合法目录和归属标签。先取得全部会话锁，再停止/删除旧容器、清除连接凭证，并把未完成消息标记interrupted。不会续旧心跳或自动重放输入。仍有活CLI持锁则启动失败；引擎未知时历史可读、执行不ready。

服务正常关机先拒绝新执行，强制停止环境并等待任务收尾，再关闭DB及锁。超过30秒以失败退出，Keeper和下次协调兜底，不宣称清理成功。写库故障阻止新执行并直接清理，故障清理不依赖再次写库。

## 预算与配置

maxBudgetUsd是同一次query的累计估算。环境重建开启新预算，不是用户硬配额；费用读取最新累计值，不能逐轮相加。连接文件在整份环境存活期间保留，确认关闭后清空。原生reset命令、逐后台任务停止、凭证热更新尚未开放。
