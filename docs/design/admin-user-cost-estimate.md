## 估算口径

1人日=8小时有效工程工作。假设熟悉当前TypeScript/React/PostgreSQL/Claude SDK/LiteLLM代码，首期维持单服务、两个角色、同一登录体系，不拆微服务，不新增组织多租户。

范围含实现、必要的类型/工程回归、角色与错误路径检查、浏览器验证；执行链变化含专用Docker/SDK夹具和少量获准真实模型回归。供应商等候、长时间负载/稳定性观察、外部安全审计、完整计费结算、跨环境生产部署不在普通首版范围。正式生产验收另排；部署版本、外部接口或数据迁移发现问题时重新估算。

人日是规划工作量，不是Codex实际墙钟运行时间。AI可以加速编辑与重复检查，但不能据此把权限、取消、凭据撤销和并发计费验证按比例压缩。

复用分三类：A现有能力换入口/轻改；B有底座、需补功能闭环；C新建核心流程。没有以页面数量或代码文件数量推导已完成度。

## 特别容易低估的地方

- SDK存在setModel方法只证明有原生入口。当前Token只放行一个模型，任务还需要更新主/辅助模型与记录；不能用一次控制RPC成功证明整个切换完成。先做小型夹具验证，再收窄06范围；目前区间较宽。
- MCP“管理员模板”已有不代表“平台共享Key”已有。当前凭据属于个人连接，脚本app可写，14需要新增信任边界，不能跟11合并为一个表单。
- LiteLLM支持metrics不代表Harbor已有指标采集、管理员查询、告警和Harbor轮次归属。当前infra/litellm.config.yaml未配置prometheus callback；接入后还需对照固定v1.106.1实际输出核查。
- 用户/会话/文件已有不代表管理员跨用户诊断API存在。应新增有界元数据查询，不能把owner校验去掉变成管理员接口。
- 当前Skill表已有builtin/private和不可变版本，平台发布复用基础明显；审批、组织分发、共享编辑则属于新增范围。
- 现有应用观测是应用所有者的业务分析，不是全平台模型网关监控。可以复用部分组件/模式，不能把同一数据源换标题宣称完成。
- 外部代理/多Worker/迁移Kata或gVisor/跨域拆分后台不属于本表；如果选这些路线，重新拆预算。

## 金钱和持续成本

不假定外包报价、个人日薪、模型价格或云套餐。开发人工预算=人日×约定人日单价R；例如A包为5R–9R，限定四包为18R–34R。AI/API实际消耗与人工预算分开记录，不用人日推测Token费用。

- 01–04等纯入口改造：首期无需新服务，新增常驻基础设施成本可接近零；仍有开发和发布验证成本。
- 05–06：无需每个模型独立容器，切换可能增加恢复请求/上下文输入费用，以实测为准。
- 17–20：新增指标/日志的存储、保留、采集与查询负担；小规模可复用现有部署，Prometheus/Grafana可选，不能承诺零资源或直接给固定月费。
- 14：本表按可信本地程序与隔离验证估算；如果改为独立Worker/外部代理，额外容器与运维另算。
- 24–27：持续有账本协调、权限回归、通知服务或备份存储/恢复演练成本，不能只算首次开发。

本轮未安装依赖、启动监控、调用模型、购买服务或切换部署。
