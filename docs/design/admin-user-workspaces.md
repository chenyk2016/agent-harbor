# 管理后台与用户工作台整体规划

日期：2026-10-28。状态：整体后台规划尚未实施；输入框模型选择与按轮切换已单独实施，见conversation-model-switching.md。
基线：main a18e6ca（v13）源码静态核对；不据此确认运行服务采用同一版本。
所属任务：T-20261028-agent-harbor-admin-user-planning。

## 1. 要解决的问题与产品边界

同一侧栏承载会话历史、模型与网关、个人MCP、技能、专家、用量与密钥；ModelsPage同时提供个人默认模型和管理员表单。后台接口已有部分管理员检查，但页面职责和导航不清楚。目标是普通用户围绕任务工作，管理员围绕平台供给、权限、成本、稳定性工作。

建议同一产品提供两个独立页面壳：`/`用户工作台、`/admin`管理后台，独立导航和默认首页。管理员登录后默认进入工作台；头像菜单出现“管理后台”，后台有“返回工作台”。普通用户不显示后台入口，直接访问页面和API仍被服务端拒绝。首期同域、同登录、同服务部署，界面分开不等于必须拆成两个服务或仓库。仅在独立网络访问、团队交付或合规边界需要时拆域名/部署。

用户端不出现供应商Base URL、模型同步、网关管理Key、平台镜像等运维概念。工程错误翻译成可行动提示，详情通过错误ID由后台排查。

## 2. 所有权与角色

首期保留普通用户、平台管理员两个角色，不先引入租户/组织复杂RBAC。后续再按需要分只读运营、运维、资源管理员；不要用“进入后台”直接获得一切数据权限。

- 平台资源：模型供给、内置MCP模板/脚本、平台Skill/专家、运行规格与接入策略。
- 个人资源：个人MCP连接与凭据、私有脚本、Skill/专家、个人默认选择、自己的应用/会话/文件。
- 会话配置：本轮模型、选用的能力、当前环境状态与操作。
- 管理员可以停用账号、回收环境、查看脱敏诊断；不默认读取用户私钥、聊天正文或文件。支持排障的内容访问需另设计明确授权、范围、期限和审计。
- 个人资源中的ownerId只能来自认证身份，不能由客户端冒充；管理员资源操作仍单独鉴权。
- 配置/密钥权限、用户业务授权、MCP上游scope、容器安全边界是不同控制，不能互相替代。

## 3. 两端信息架构

### 用户工作台

主导航只保留：新建对话/会话历史、我的应用、能力库。能力库页签为“技能、专家、工具连接”，每项区分平台提供/我的，允许筛选，不把三种资源的存储模型强行合并。

头像菜单：个人设置、用量与额度、访问密钥（高级）、退出；管理员额外有管理后台入口。

会话输入框内常驻模型选择器，位于右下角发送按钮旁；显示用户可用的产品名和短说明。能力选择使用单独入口，显示本会话已选择项。空态与已有对话使用同一输入框交互。每轮不强迫重选，记住该对话选择；个人默认只影响新对话，修改默认不追改旧对话。

生成中首期禁用切换；空闲时选择对下一轮生效。成功切换必须以服务端确认和执行端实际模型为准，失败保留原选择并说明原因。历史轮次保存模型快照；跨模型上下文、辅助请求、凭据与用量归因须专项验证。当前实现仍为会话固定，规划不代表已支持。

### 管理后台

建议一级导航七项，避免把所有功能铺成同级菜单：

1. 总览：待处理故障、今日流量/观测费用、活跃环境、采集状态和最近变更；卡片链接详情，非孤立数字。
2. 模型与网关：模型目录、供应商连接、授权/默认、网关运行与请求诊断、用量/预算。
3. 能力管理：平台MCP、平台Skill、平台专家、接入策略。
4. 用户与额度：用户状态、使用权限、并发/存储/模型额度、访问撤销。
5. 运行与应用：会话环境/任务诊断、发布实例/构建/存储/网关路由、故障协调。
6. 监控与事件：告警、采集健康、操作审计、故障关联查询。
7. 系统设置：只展示有明确安全操作流程的配置，包含保留策略、备份状态、身份入口和运行规格；不提供任意shell、任意文件编辑或任意Docker参数。

首期只实现有数据和操作闭环的页面。尚未接入的能力标“未接入”或隐藏，不能用假统计填充。

## 5. MCP应该由谁配置

把程序定义、连接实例、凭据归属、会话启用拆开，避免一个“配置MCP”混合四种权限：

- 管理员定义平台可选模板和固定命令、脚本版本、网络规则、允许接入的远程origin、是否开放私有脚本。
- 用户为自己创建连接，填写自己的Key/OAuth授权，测试并启用；不需要逐个由管理员手工录入。首期沿用管理员目标允许列表，后续按业务需要增加目标申请流程，不能默认任意外网。
- 用户选择哪些获准连接用于任务；当前v13解析用户启用连接，会话级选择尚需单独设计，不标已实现。
- 平台提供Key的MCP是新增类型，不与个人凭据混用。程序和依赖需固定、只读、不可被用户替换，工具不能暴露环境/任意文件或把认证发送到任意地址。当前脚本app副本可写，不能直接承载此保证。
- 凭据归属建议显式枚举为user/platform；platform凭据绑定平台工具版本与允许范围，不允许用户脚本引用其secret ID；首期不做跨用户共享个人连接。
- 用户填自己的Key无需对本人保密，但仍需防跨用户读取、意外日志/成果泄漏；管理员页面只显示配置状态、更新时间和撤销/重配入口，不显示明文。
- 沿用原生MCP客户端，不因为增加后台而重新引入MCP协议网关。远程直连缺少的逐调用审计或强即时撤销必须标明；若确实需要，另评估代理，不把UI规划当实现。

## 6. 模型网关监控

需要监控，按“能否用、为什么慢、钱花在哪、谁在用、数据是否完整”组织。网关HTTP成功不等于Agent任务成功，任务成功不等于用户验收。

| 监控面 | 建议指标 | 维度/行动 |
| --- | --- | --- |
| 可用性 | 请求量、成功/失败、429、超时、5xx、认证失败 | 模型/供应商；定位上游故障与本地错误 |
| 性能 | 网关总耗时、上游耗时、首Token时间、P50/P95、在途请求 | 模型/供应商；与用户点击到首字的端到端体验分开 |
| 用量与成本 | 输入/输出/缓存Token、观测费用、未知费用请求、统计延迟 | 用户/模型/供应商/会话；缓存类别与价格缺失明确 |
| 授权与预算 | 凭据创建/撤销未知态、过期、额度拒绝、RPM/TPM、并发 | 用户/模型；模型停用与任务停止分别记录 |
| 平台资源 | 服务/PG/Docker/磁盘健康、环境数、启动/清理耗时 | 全局/环境；unknown必须显示，不显示“已停止” |
| MCP | 发现/初始化失败、依赖安装失败、工具超时、连接异常 | 不同来源注明；当前无完整逐调用网关审计 |
| 任务结果 | 完成/失败/中断、工具错误、运行时长 | 会话/轮次；不是模型质量或业务成功率 |

首期站内告警：网关不可用、请求失败异常、费用/预算异常、待撤销凭据、环境清理未知、磁盘不足、采集延迟/失联。阈值配置化并带最小样本、持续窗口、去重/恢复，具体数值在基线测量后设置，低流量不能靠百分比误报。外部通知仅规划，不创建定时器或发送消息。模型探活默认被动；手动带模型请求的诊断明确说明可能产生费用，不能后台自动消耗真实模型。

指标页必须显示采集时间、刷新时间、覆盖范围、延迟/缺失。网关模型列表同步成功不代表真实工具调用和流式兼容通过；分别标配置/连通/协议夹具/真实调用验证。

请求记录建议包含Harbor用户/会话/轮次/attempt与网关request ID、请求模型和实际模型（上游提供时）、开始结束、状态、重试序号、Token与价格版本/币种。当前只精确到Key的历史费用不得补猜每轮；重试attempt单列，不能把一次用户消息当一次模型请求。未知计价不算零，不与SDK估算重复相加，网关观测不等于供应商最终账单。

Harbor拥有用户授权、业务归属与展示；LiteLLM继续拥有推理转发、有效路由和可提供的网关统计；平台采集器整合指标。优先复用LiteLLM原生metrics/spend接口，不重写数据面。官方文档当前提供请求/延迟/Token/费用指标，但现用v1.106.1的具体字段、许可范围、部署开关与采集实际覆盖需按固定版本核验。

聚合指标只使用模型、供应商、状态等有界标签；用户/会话/轮次ID进入有访问限制的明细库，不把它们全塞Prometheus标签。不默认记录请求/响应正文、Authorization或Key；前端不持有网关管理Key，指标接口仅内网。

现有应用“运营”页属于应用所有者的流量/转化/质量/版本分析，保留在“我的应用”；后台看跨应用资源和服务健康，两者共享底层采集可以，但不混用UV、模型请求、会话轮次等口径。

## 7. 技术切分与状态生效

第一阶段独立AdminLayout/UserLayout和路由，不拆数据库/执行服务。新增统一账号capabilities响应（建议扩展/auth/me），从服务端单一权限判定派生canManageModels、canManageUsers、canManagePlatformTools等；不再依赖模型目录里的admin字段表达全平台身份。

API按/admin/*和个人资源路径区分，所有入口服务端检查。页面隐藏只是交互，不是授权。后台读取可用但无写权限的未来角色应与写操作能力分开。

模型状态建议分别展示enabled、同步状态、最近验证、告警健康，不合成一个“可用”。当前供应商/模型配置不可变，新版本替换与旧会话影响需显式；只保存UI表单不代表网关同步完成。

配置变更先显示影响对象与生效时间：默认值只影响新选择、连接变更下次环境重建、下架阻止后续执行、立即停止必须走生命周期确认。超时读回确认，不重发可能产生副作用的写操作；未知保留待核对。

后台可读诊断先覆盖元数据，危险操作固定为停用/撤销/关闭/核对等业务动作。身份系统主密钥、数据库URL、任意镜像/挂载仍留运维配置，首期不制作万能配置编辑器。

## 8. 实施顺序与成本

| 阶段 | 内容 | 相对成本 | 验收重点 |
| --- | --- | --- | --- |
| A：先解决杂乱 | 独立后台壳、统一权限响应，迁移已有模型/用户管理，用户导航精简 | 低至中；主要UI/路由/能力接口 | 两角色导航、直达拒绝、个人功能无回归 |
| B：用户模型体验 | 输入框常驻选择；按轮选择/快照；网关凭据与SDK切换 | 中；跨授权/Runner/费用记录 | 确实切换、失败一致、历史不改、跨模型上下文 |
| C：补运维闭环 | 模型/网关指标、最小请求关联、异常详情/站内告警 | 中；采集/数据口径/查询 | 缺失不作零、请求重试不重算、诊断不泄密 |
| D：平台能力供给 | 平台MCP/Skill/专家发布版本、平台凭据、作用范围、后台维护 | 中至高；资源归属/安全/版本生效 | 个人私钥不越权、私有脚本不得取平台Key |
| E：规模化治理 | 月度用户累计预算、预留并发账本、细分角色、外部告警/账单对账 | 高；按实际用户规模推进 | 并发超额/延迟/退款与恢复等专项 |

A不必等待B。首期后台提供基本观测摘要即可，完整可观测性与商业计费不要阻塞界面职责拆分；完整告警平台、自动fallback、组织多租户、自动调价与任意插件市场不在首期。

当前Key预算按环境创建，不是用户/会话累计硬封顶。新增阶段E之前必须保留此说明；不要在阶段A把现有字段改名成“用户月度预算”造成假能力。

## 9. 验收清单

1. 同一业务流程分别以管理员/普通用户走完，截图可看出不同导航；普通用户没有供应商和平台设置。
2. 普通用户直达/admin页面/API、伪造角色或资源owner被拒绝；管理员仍不能回显个人Key。
3. 管理员配置模型→同步确认→用户输入框可见→实际任务使用一致；下架及无可用模型有明确状态。
4. 生成中不能误切换；空闲切换后的真实网关授权、SDK主/辅助模型、历史快照与失败恢复一致。
5. 用户创建个人MCP填写自己的Key正常；跨用户连接/源码/凭据不可访问；平台Key不能被私有脚本引用。
6. 断开网关/计价缺失/统计延迟/请求重试分别演练，界面区分故障、未知和零；不默默切换模型。
7. 模型请求ID可关联任务attempt，统计覆盖说明准确；没有真实账单核对不得宣称结算准确。
8. 停用用户和关闭环境保留现有停止确认机制，未知状态阻止重用。
9. 后台默认不采集聊天正文/认证头，脱敏错误可通过ID排查；日志与接口中无密钥。
10. 浏览器验收、真实Docker/SDK、真实模型、供应商账单/业务验收分别留证，不互相替代。
