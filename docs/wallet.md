title: 额度与计费
---

Harbor 用人民币额度管理成员的模型消耗。额度属于内部账本，可以累计，不能提现；供应商仍按自己的账单规则收费。

## 查看自己的余额

在工作台打开「设置 → 账户与用量」，查看「钱包」中的「我的额度」，可以查看可用余额、预占、累计获得和消耗、本月消耗、近期流水及模型用量。管理员也能在「用户」详情查看这些数据。

**预占**是为正在执行的模型请求暂时留出的额度。请求完成并拿到完整用量后，按实际消耗结算，未使用的部分退回可用余额。一条消息可能触发多次模型请求，因此按请求及 Token 计费，按消息条数无法准确估算。

## 为成员分配额度

| 方式 | 在哪里设置 | 生效规则 |
| --- | --- | --- |
| 邮箱自助注册赠送 | 随自助注册提供 | 当前每个新账号固定 10 元一次，暂不随后台赠送设置调整 |
| 其他新账号的注册赠送 | 管理后台 → 计费设置 | 按当前设置向首次创建的账号赠送一次；设为 0 可关闭这项规则 |
| 手动赠送 | 用户详情，或计费设置中的批量赠送 | 先核对成员、金额和合计，再确认 |
| Plus 月赠 | 用户详情开通 Plus，计费设置调整金额 | 按当前设置发放，每个上海自然月最多一次 |

按安装指南创建的全新托管实例，后台「注册赠送」与「Plus 每月赠送」初始均为 **0 元**；邮箱自助注册的固定 10 元仍单独生效。已有实例保留当前设置，使用前以计费设置页面为准。

Plus 是管理员授予的资格和到期时间，产品内没有购买或支付流程。取消或到期会停止后续赠送，已获得余额保留。调整赠送金额只影响之后的发放。

批量赠送的「全员」指预览时所有未停用成员，之后注册的成员不加入这次名单。提交结果不明确时先查看流水和原批次结果，避免另建一批重复赠送。

## 模型价格怎么设置

在「模型与网关」打开模型的「价格」，分别填写输入、输出、缓存读取和缓存写入单价，单位为**元 / 百万 Token**。

例如某模型输入单价 1 元、输出单价 2 元，一次请求使用 100 万输入 Token 和 50 万输出 Token，基础费用为 2 元；有缓存用量时再按对应单价计算。

每次保存都会形成新价格，历史请求沿用发起时的价格。四项可以明确填 0，但未配置价格会阻止该模型生成。金额计算精确到百万分之一元，单次费用向上取整到该精度。

## 余额不足或扣费不明时会怎样

余额不足时，新模型请求会被拒绝，补充额度后再按原会话继续。余额是成员在 Harbor 的使用控制，不能视为供应商账单的绝对费用上限。

请求遇到上游错误、用量缺失或服务异常时，可能保留预占并显示待核对。管理员应在「扣费核对」查看依据并确认金额，不能把未知消费当作 0。客户端中断导致用量不完整的请求可能由平台免收；已经完成的结算不会因随后断开而退款。

## 三种金额为什么不同

| 金额 | 用途 |
| --- | --- |
| Harbor 人民币扣费 | 按平台价格从成员额度结算 |
| 网关供应商美元成本 | 观察供应商成本，供管理员分析 |
| SDK 美元估算 | 模型运行诊断信息 |

它们使用不同口径，不能相加或直接作汇率换算。供应商账单需要单独核对；成本缺失表示未知。

按安装指南创建的实例默认启用钱包。`AH_WALLET_ENABLED=false` 会关闭 Harbor 扣费，受管模型仍可能直接调用供应商；这一设置应由部署管理员按实际成本管理要求决定。
