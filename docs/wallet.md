# 人民币额度、Plus与模型扣费

平台余额以人民币额度显示，可累计、不提现。SDK美元估算和LiteLLM供应商费用摘要保持为诊断信息，不参与本钱包扣款。

## 管理与使用

管理员在“模型与网关”管理：

- 注册赠送默认10元，可调整，0关闭。用户首次创建的事务内发放一次。部署前已存在的用户不追发，需通过手动赠送补充。
- Plus月赠默认10元，可调整，0关闭。首版是管理员授予的Plus资格与到期时间，不涉及支付。开通当月发放，每个上海自然月最多一次；取消/过期保留余额。后台每分钟补齐漏发月份，服务重启也协调补发；每笔按处理时配置金额落账。金额调整不重算已发月份。
- 手动赠送按确定的用户ID名单、每人金额、备注与批次ID提交。页面“全员”指预览时已有且未停用的全部用户，后注册用户不加入旧名单。同批次重复提交不会重复入账；同ID改变内容返回冲突。
- 部署单价按“元/百万Token”设置输入、输出、缓存读取、缓存写入四项。每次保存生成新的价格版本；允许明确填写0，未配置时不允许该部署生成。缓存不单独优惠时可填与输入相同价格。价格不回溯历史，请求保存价格版本快照。
- 用户从“用量与密钥”的“我的额度”查看可用余额、预占、累计获得/消费、本月消费、最近100笔收支与模型用量。管理员选择用户可看相同数据。

计费使用整数微元（1元=1000000微元），每请求按Token乘单价后向上取整到1微元。余额与历史流水永久关联，不随会话/环境重建重置。

## 请求链路

`Runner / 原生Claude SDK → Harbor /inference/v1/messages → LiteLLM → 上游模型`。

模型循环和工具仍由原生SDK执行。Harbor计费代理只处理Messages及count_tokens，不开放任意网关管理路径。Runner持有独立的Harbor钱包授权Token，数据库保存索引哈希、加密保存秘密；真实LiteLLM Key只在宿主转发时使用，钱包Token不能直接调用LiteLLM。每请求检查用户、部署/版本权限、绑定状态和当前价格版本，固定实际 route 后转发。

未启用网关基础策略时沿用首版全余额预占。启用AH_LLM_POLICY_FILE后改为请求字节数加余量及最大输出的保守估算预占，余额足够时可有多笔在途请求，不额外设置模型并发上限。估算不是精确Tokenizer保证。收到完整Messages usage后按价格快照结算，退回未使用部分。相同请求结算操作只扣一次；SDK重试若实际重新发起上游调用，属于另一笔真实请求。

余额不是供应商单次调用的硬成本封顶。单次实际消费大于预占时，可使用尚未被其他请求占用的余额；其他请求预占不会被挪用，仍不足的部分由平台承担并记录waived；下一次调用余额不足返回402。用户额度控制不按消息数；既有任务并发、超时、原生SDK安全上限等运行保护仍保留。

客户端中断导致用量不完整时，平台承担未知费用，本次免收并释放预占，保留免收流水；actual和Token保持未知，不伪造零消费。已完成结算不会因稍后的断开而退费。上游错误、usage缺失和进程崩溃仍保留预占、状态unknown。管理员在用户详情填写实际扣款与依据，扣款不得超过预占；确认无消费或决定平台承担时可填写0释放。基础策略下，未知请求只保留该笔预占，其他可用余额仍可用于模型请求；原全余额模式仍会阻断新请求。不自动重放用户任务。明确的网关预算拒绝会释放预占并返回额度提示，不转成待核对锁单。

## 部署

1. 备份控制面数据库、AH_DATA_DIR和私有环境文件，确认无活动任务后停服。
2. 构建并受控执行0011_wallet.sql；迁移给已有用户建立0余额账户，不赠送、不扣历史费用。
3. 配置AH_WALLET_INFERENCE_URL，钱包随托管网关自动开启；可设AH_WALLET_ENABLED=false关闭。该地址指向Runner可达的Harbor节点入口，例如http://host.docker.internal:4319/inference。LiteLLM管理地址仍由AH_LITELLM_MANAGEMENT_URL配置。
4. 重启会回收旧环境/Key。新环境使用钱包Token；无需修改Agent工具循环或Runner镜像。
5. 管理员为每个部署设置四项平台价格，并给已有用户赠送额度/开通Plus；新用户自动按注册规则入账。没有价格或余额时明确拒绝，不回退旧直连出口。

关闭钱包开关会回到原直连模式，不再执行本钱包扣款，因此该开关仅属于受控运维配置，不能由普通用户修改。账本和未知预占保留。未启用时页面显示警告。

## 验证边界

单元/PG测试验证精度、幂等、并发、Plus日历、未知结算、权限与旧消息限额不再拦截。真实LiteLLM/Docker/SDK使用本地确定性模型响应验证逐请求扣费和Read/Write/Bash；这不证明实际供应商Token统计、价格或模型质量。真实供应商、账单对账、负载/故障矩阵和生产多租户隔离仍需单独验收。
