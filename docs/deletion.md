# 对话与应用：直接删除

不设回收站，不支持恢复。对话列表的行菜单提供“删除对话”；应用画廊、编辑页设置和应用会话菜单提供“删除应用”。应用删除须输入当前应用名称。应用的开发对话不能单独删除，需要删除所属应用。

点击确认后，服务先持久化删除意图，拒绝该资源的新消息、文件读取、修改和执行，再停止任务并确认容器/凭据清理。完成后才从列表移除；进行中显示进度，失败显示“删除未完成”并允许重试。失败不提供恢复或取消删除；关闭提示窗口只关闭窗口。再次点击删除复用同一清理任务。

| 对象 | 删除内容 |
| --- | --- |
| 普通对话 | 聊天消息、事件、会话记录、上传和生成文件、SDK状态、该会话的依赖环境及能力快照、专属容器、模型绑定和旧MCP调用/绑定记录 |
| 应用 | 上述开发对话资源、预览和正式路由/容器、构建容器、源码Git历史/版本、构建与部署文件、操作日志、归属明确的导出文件、专属运行镜像引用、两个业务数据库及角色、应用观测库中的该应用数据、应用控制面记录 |

个人技能、专家、MCP连接、平台运行镜像及其他应用共享资源不随单个对象删除。镜像仅移除该构建的命名引用，不强制删除其他容器正在使用的镜像。文件操作不跟随符号链接；数据数据库名称由实例根、应用编号和环境确定，不接受客户端指定路径或数据库名。

账务流水、必要用量/请求与审计元数据独立保留，不改变余额、已用额度或历史费用。清理完成后仅保留不含聊天正文的删除回执（对象编号、归属、阶段、时间及结果），用于重试去重和审计。这些回执不是可恢复副本。此功能清理在线资源，不改写已有离线备份、共享构建缓存或已导出的外部观测数据。

## API与失败恢复

- `DELETE /api/sessions/:id`：返回202及删除任务。
- `DELETE /api/applications/:id`：JSON为`{"confirmName":"当前应用名称"}`，返回202及删除任务。
- `GET /api/deletions/:id`：仅归属用户可读；返回running/failed/completed和阶段。
- `GET /api/deletions`：仅列本人最近100条任务。

完成时消息、事件、应用记录及文件实际清除；旧链接不可继续读取。未确认停止、网关撤销、数据库或文件删除失败时保留检查点，禁止复用该资源；其他资源可正常使用。running任务在服务启动时接续，failed任务由用户明确重试；阶段操作可重入。不得将202、超时、容器查询失败或列表隐藏当成删除完成。

已有文件写入尚未结束时会拒绝本次删除登记，等待传输结束后重试；登记后不再接受新写入。收到删除意图后，活跃SSE和文件读取会被中止；已有模型任务沿用原生停止/清理流程，不实现另一套Agent循环。

## 安装与验证

先停服务并备份控制库，再应用`0017_resource_deletions.sql`，完成正常构建后重启。运行`npm run check`及隔离PG中的`npm test`。`node tests/deletions-verification.mjs`另建一次性PG/Caddy/真实测试容器及业务数据库，验证失败重试、越权、文件/镜像/数据库清理和其他应用不受影响；需要本机已有`agent-harbor:delivery-v29`测试基础镜像。默认不连接现有用户数据，不调用模型。
