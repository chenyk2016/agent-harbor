# 使用 WorkBuddy 专家包

Agent Harbor直接读取WorkBuddy的`.codebuddy-plugin/plugin.json`和Agent Markdown，不要求把正文拆成角色、方法、输出三个栏。已有旧格式专家和会话保持原行为。

## 使用流程

1. 进入“专家”，点击“导入WorkBuddy包”，选择原ZIP。也可以创建专家，编写完整Markdown，再编辑生成的包文件。
2. 详情可查看全部包文件、完整Agent、包内技能、头像等资源；下载原包保留上传ZIP原始字节。
3. 点击“召唤专家”。包内技能自动准备；保存不会修改个人Skill默认开关。准备完成后自动创建固定版本会话，发送消息才启动模型。
4. 需要外部连接时，在“网络与外部连接”中完成连接。纯角色专家不需要空的安装步骤。
5. 编辑包文件后“保存包新版本”；未知字段、未编辑文件和二进制资源保持。历史只读，旧会话不跟随更新。

当前导入作为一位新专家；后续修订在详情编辑保存。原包中的语义版本与平台修订号分开，平台不自动伪造作者版本。新建的最小包可以运行；上架WorkBuddy市场所需作者邮箱、头像等资料由作者自行补充，平台不虚构。

## 运行原理

服务从agentName读取主Agent，使用SDK的agent/agents选项创建主对话，保留完整Markdown。声明的成员通过原生Agent调用、SendMessage和任务工具协作，不在服务端另写模型循环。

包内Skill作为本修订私有能力准备。运行时将同名技能放入只读生成的`.claude/skills`，只让Claude加载这份生成配置，不加载可写workspace的项目配置。因此原包短名可直接调用，仍由原生Skill执行；个人默认插件保持独立。

SDK0.3.306的AgentDefinition.skills在主Agent中未实测到正文预加载；兼容层因此补充声明技能的静态上下文，并给出实际资源目录，不依赖该字段制造加载成功的假象。技能实际调用和动态处理仍由Claude原生执行。带动态命令的Skill在“预加载时即执行”这一语义尚未单独验证；不能把静态预加载验证推广到所有扩展。

原包只读资源位于`/opt/harbor-skills/workbuddy-source`，工作成果写入`/workspace`。可执行位随ZIP保存，依赖准备沿用已有Skill构建引擎；无声明的pip/npm依赖不会被猜测安装。

## MCP与连接器

包中可以用dependencies.mcpServers指定一个或多个配置文件，也可以使用根`.mcp.json`。支持远程HTTP/SSE声明，以及x-workbuddy的none、Token表单、OAuth授权。连接时实际初始化并查询工具，未就绪不召唤。

OAuth使用MCP官方SDK做发现、动态注册、PKCE和Token交换；固定回调为`PUBLIC_ORIGIN/api/expert-oauth/callback`，服务商需要允许相应客户端注册/回调。状态绑定用户、一次消费、10分钟过期。凭据使用服务数据根`.connection-key`加密，数据库只保存密文；该密钥需随数据一起备份，不能放进专家包或Git。

凭据只在运行时注入临时连接文件，不进入专家ZIP、会话快照或页面持久化。下一轮前重读连接配置，变化时重建执行环境；断开连接会关闭仍依赖已撤回连接的本用户专家环境。OAuth过期后在下一轮前尝试重新连接/刷新；长任务执行途中Token失效仍可能导致该次工具调用失败，不自动重放未知外部操作。

WorkBuddy私有连接器的服务地址、账户和授权不能从包内自动取得。管理员可在数据根配置`connector-providers.json`，将原连接器ID映射到本平台可用的远程MCP提供者：

```json
{
  "your-connector-id": {
    "type": "http",
    "url": "https://your-service.example/mcp",
    "x-workbuddy": {
      "displayName": { "zh": "企业连接器" },
      "auth": { "type": "oauth" }
    }
  }
}
```

配置变化后按新定义重新授权。没有对应提供者时，详情明确列出缺少的连接器，拒绝缺能力召唤；不能把换一个同名地址等同于已验证腾讯官方连接器的工具语义。stdio MCP服务器不在宿主执行，当前需提供远程服务。

## 在线资料和工具边界

运行镜像包含curl。技能需要在线资料时，在该包详情保存需要允许的域名；只改变该包下一轮的Bash网络规则，保留其他管理员隔离限制。普通会话不受影响。模型网关、MCP连接与Bash网络是不同通道。

包不能提升平台工具、文件或预算权限。Agent.tools保留在原件中，工具由平台统一分配。平台仍没有可用的原生WebSearch服务；不能承诺依赖该服务的任务效果等同WorkBuddy。没有可用能力时应补接对应连接器，不伪装为调用成功。

官方design-experts.zip的参考库本身依赖网络，并非带有58份离线文件；其中stripe.md示例地址在本次核查返回404。平台保留原包，不偷偷修改作者链接。有效公共资源的下载与失效链接分开验证。

## 数据、升级与验证

迁移0004增加包内Skill作用域和用户连接凭据表；旧版本不修改。新运行镜像为agent-harbor:0.5.4，旧镜像会在模型请求前拒绝新格式任务，旧会话仍保留原镜像。

部署前备份数据库、整个服务数据根（包括连接加密密钥）、私有环境配置，停服迁移并构建新镜像，再在新镜像准备原启用技能。保持旧镜像和旧会话目录。

兼容设计保留在仓库的 `docs/plans/workbuddy-experts-compatibility.md`。验证按原包/格式/运行/真实业务分层：官方ZIP、源文件、PG事务与用户归属、实际Docker/SDK、MCP和OAuth协议夹具、网页分别核对。公开格式兼容并不意味着复制WorkBuddy的腾讯私有服务、登录态或同一模型效果。
