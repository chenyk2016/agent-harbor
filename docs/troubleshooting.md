先按现象找到对应问题，再检查配置和状态。不要在结果不明时重复创建实例或反复发送同一任务。

## 工作台打不开或无法启动

在项目根目录运行以下检查，实例目录替换为实际路径：

```sh
docker info
npm run harbor -- doctor --dir /absolute/instance
curl --fail --silent --show-error http://127.0.0.1:4318/api/health
npm run harbor -- verify --dir /absolute/instance
```

这些检查不调用付费模型。健康接口预期返回 `ready: true`。

- Docker 连不上

  启动 Docker Engine，确认服务账号有权限，并安装 Compose v2

- 端口被占用

  检查实例端口；新实例可用 `configure` 参数另选端口，不要重配已有实例

- 数据表缺失

  停止 Harbor，对正确实例重新执行 `harbor install`，完成后再启动

- 缺少管理员密钥

  首次 `harbor init` 需提供 `AH_BOOTSTRAP_ADMIN_KEY`，格式见 [账号与登录](identity.md)

- 初始化凭据写入未确认

  保留实例与错误信息，核对 `first-admin.key` 和初始化结果，避免删除后重建

- 网页能开但尚未就绪

  查看服务日志与 `doctor` 结果，确认数据库、网关和执行环境状态

## 登录失败或入口缺失

- 访问密钥被拒绝

  使用本实例的 Harbor 密钥，确认账号未停用、网页登录密钥未关闭

- 管理员密钥改了仍无效

  确认服务加载的是正确环境文件、没有同名进程变量覆盖，并已重启

- 邮箱登录入口缺失

  检查固定公开地址、至少 32 字符的认证密钥和数据库准备情况

- 注册入口缺失

  还需 HTTPS 和托管钱包网关，且未设置 `AH_WORKBENCH_REGISTRATION=false`

- 反向代理后循环登录

  核对浏览器地址与 `AH_PUBLIC_ORIGIN` 完全一致，并检查 HTTPS 和反向代理

- 登录后没有管理后台

  检查当前内部用户 ID 是否列在 `AH_ADMIN_USERS`，注册不会自动成为管理员

完整设置见 [账号与登录](identity.md)。

## 没有模型或模型请求失败

先在「管理后台 → 模型与网关」查看模型状态。模型需要启用、授权给当前用户并完成价格设置；当前用户还需有足够余额。

接入向导会区分密钥错误、模型不存在、协议错误、工具或流式测试失败。按提示修改后在同一向导重试，不必重新创建一套配置。具体排查见 [接入和管理模型](llm-gateway.md)。

余额被预占时，到「我的额度」查看明细；待核对请求由管理员在「扣费核对」处理，见 [额度与计费](wallet.md)。

## 任务断开、停止或无法继续

- **关闭网页或网络断开：** 重新登录，打开原会话查看进度。断开网页不会主动取消服务端任务。
- **消息发送后结果不明：** 先查原会话；界面提供重试时使用原提交，避免另发一条造成重复执行。
- **任务无法启动：** 运行 `harbor doctor --dir /absolute/instance --runtime`，查看镜像、Docker 和沙箱检查结果。
- **服务重启后任务中止：** 查看已有产物和最后状态，确认后显式提交下一轮。服务不会自动重做任务。
- **删除尚未完成：** 等待文件传输结束，再从原对象重试清理，见 [删除与数据保留](deletion.md)。

## 应用预览或登录失败

| 现象 | 处理方法 |
| --- | --- |
| 看不到创建应用入口 | 检查创建者授权、应用访问地址、应用数据库和 Caddy 是否配置并可用 |
| 预览为 502 或待核对 | 在应用工作台查看对应环境记录，先「核对运行状态」，再检查 Caddy、容器和数据库 |
| 邮箱可登录，Google 回跳失败 | 检查当前环境的 OAuth 客户端、准确回调地址、允许账号和认证域 HTTPS |
| 测试数据在正式环境找不到 | 测试与正式环境数据独立，确认当前所选环境 |

设置见 [应用创建](applications.md) 和 [应用访客登录](application-login.md)。

## 备份恢复失败

核对程序版本、原运行镜像、备份完整性和目标是否为空。保留失败目标与日志，使用新的空目录和空数据库处理。恢复步骤与备份范围见 [团队部署与备份](deployment.md)。

## 提交问题时附什么

提供程序版本或提交、系统与 Docker 版本、触发步骤、预期结果、脱敏错误码和检查结果。凭据、原始会话和真实用户文件不要放进公开问题中。
