Harbor 希望让你既能把工作交给 Agent，也能看清过程、拿到结果，并决定什么时候发布。

## 任务围绕会话和文件展开

**会话**是一组连续的对话及其工作区。例如，先上传报名表让 Agent 去重，再要求它按渠道汇总，两轮操作使用同一份工作文件。

**工作环境**是执行工具时使用的临时环境。它可以关闭和重新创建；对话和工作文件由服务保存。临时进程、内存和临时文件不会随环境重建恢复。因此，重要结果应写成工作区里的文件。

浏览器用于提交任务和查看结果，任务在服务端执行。关掉页面后可以回来继续查看；停止任务和关闭页面是两个操作。

[对话与任务](session-lifecycle.md) · [工作区与文件](workspace-files.md)

## 方法、助手和工具各有用途

| 概念 | 用来做什么 | 例子 |
| --- | --- | --- |
| 技能（Skill） | 保存做事方法、脚本和资料 | 约定报名去重与汇总规则 |
| 专家 | 为特定任务组织说明和技能 | 一个按既定方法工作的数据分析助手 |
| MCP 连接 | 向 Agent 提供可调用的工具 | 查询已连接系统中的记录 |

技能和专家保存为版本，已有会话使用固定版本，避免在任务中途被后续编辑改变。连接的授权则由当前账号管理，使用前需要完成连接和权限设置。

## 先试用，再发布

应用有源码版本、测试预览和正式发布三个不同状态。你可以修改源码、用测试数据检查，再把确认的版本发布给访客。

测试与正式数据分开，防止试填污染业务记录。代码回滚用于恢复页面和行为，已经产生的业务数据仍保留；它不是数据库恢复。

[创建、预览与发布](applications.md)

## 数据帮助判断，行动由你发起

报表用于回答发生了什么，只读问数用于帮助理解获准数据。例如发现报名率偏低，可以先核对访问量、事件口径和样本，再决定是否简化表单。版本之间的差异本身不能证明改版产生了效果。

问数不会直接修改业务记录或自动发布新版本。确认修改方向后，再进入应用编辑对话。

[应用数据与分析](application-observability.md)

## 自己管理部署与使用范围

自托管让部署者管理工作文件、配置和成员权限。使用远程模型与工具时，需要把相应内容发送给供应商；自托管并不代表任务完全离线。

管理员负责提供模型、分配使用范围和内部额度。成员可以查看自己的任务与产物。Harbor 当前适合个人和受信小团队，开放给陌生用户前需要额外评估执行环境的隔离。
